# VIEW 노트 — 3D 픽셀 렌더러 (v0.2 라운드 1)

> 뷰 층(`godot/view/**`) 담당이 쓴 문서. 계약은 `ARCHITECTURE.md`, 방향은 `DIRECTION.md`.
> 뷰는 규칙을 모르고 상태를 바꾸지 않는다. `Game.state`를 읽고 `Game.event` / `Game.state_replaced`만 듣는다.

## 1. 파이프라인 (한 장 요약)

```
CityState ──▶ CityMesher(층별 ArrayMesh, 파생 구조물) ──▶ SubViewport(저해상도 3D, 직교 카메라)
                 │                                             │  city.gdshader: 3단 톤 + 높이맵 그림자 + 복셀 빛
                 ├─ lights[]  ──▶ LightGrid(복셀 빛 3D 텍스처)  │  sky.gdshader: 하늘·능선·스카이라인
                 └─ emitters[] ─▶ Fx(셰이더 입자) / People      │  outline.gdshader: 깊이 외곽선(곱하기)
PixelAtlas(512² 아틀라스: 자재·창·소품·바닥·가구·간판 글자) ──┘
                                                   SubViewport 텍스처 ──▶ 정수배 최근접 확대 ──▶ 화면
```

| 파일 | 하는 일 |
|---|---|
| `view/CityView.gd` (+`.tscn`) | Control. 뷰포트·카메라·입력·API(`set_floor_cut` `rotate_view` `zoom_step/set_zoom` `pick` `project` `show_ghost/spots/zones` `clear_overlay` `set_time_override`, 시그널 `cell_tapped` `view_changed`) |
| `view/CityMesher.gd` | 셀 → 메시. 외관(층별) + 층 컷(실내) + 파생(다리·외벽 계단·반 칸 돌출·옥탑·굴뚝·간판 배치) |
| `view/PixelAtlas.gd` | 모든 텍스처를 실행 시 코드로 그림. 간판 글자는 픽셀 폰트를 CPU에서 래스터해 아틀라스에 구움 |
| `view/LightGrid.gd` | 높이맵(그림자·맞닿음 음영용)과 복셀 빛(네온·창 번짐용) 텍스처 |
| `view/People.gd` | 사람(뷰 전용 연출). LOD 3단 |
| `view/Fx.gd` | 김·연기·향·불꽃·물방울·비둘기·먼지 + 비행기 |
| `view/SkyTex.gd` | 배경 스카이라인 텍스처 생성 |
| `view/Sandbox.gd` (+`.tscn`) | 뷰만 띄우는 씬 |
| `tools/fake_city.gd` | `FakeCity.build(preset, seed, grid)` — 시뮬 없이 CityState 생성 |
| `data/render.json` / `data/visuals.json` | 렌더 수치 / 외형 매핑 (F5 핫리로드) |

### 카메라 수학
- 직교 카메라, 방위 45°+90°k, 고도 30° → 지면 모서리가 정확히 2:1 픽셀 계단.
- 칸 반폭 8px(줌 ×1 기준) → `ppu = 8·√2`. 한 층 = 8px이 되도록 `floor_h = 8/(ppu·cos30°) = 0.8165`. 벽 타일 16×16 텍셀이 줌 ×2에서 텍셀 1 = 픽셀 1.
- 카메라는 픽셀 격자에 스냅하고, 남는 소수 픽셀은 확대된 그림을 밀어 부드럽게 스크롤한다(`pixel.subpixel_scroll`).
- 픽셀 중심이 텍셀 경계에 걸리면 깜빡이므로 카메라를 0.1텍셀만큼 일부러 어긋나게 둔다(줌마다 값이 다름).
- 내부 해상도 = 실제 창 폭 ÷ 정수배(`pixel.target_width` 270 근처가 되게). 540창 → ×2, 1080폰 → ×4.

### 조명 (실시간 광원 0개, 그림자 맵 0장)
- `city.gdshader`가 직접 계산: 윗면 밝음 / 해 받는 옆면 / 비낀 옆면 / 그늘 — 면마다 단색 톤. 그늘은 보라·파랑 쪽으로 색상이 밀린다.
- 그림자: 기둥 높이를 32×32 텍스처에 넣고 프래그먼트에서 격자 DDA로 해 방향을 따라간다 → 칸 경계에 딱 맞는 또렷한 그림자, 해가 움직이면 그림자도 움직인다.
- 맞닿는 곳(벽 밑·높은 벽 옆 지붕)은 어둡게, 낮은 쪽으로 떨어지는 지붕 가장자리는 밝게 — 같은 높이맵으로 계산.
- 밤: 네온·창 빛을 32×14×32 복셀 격자에 쌓아 3D 텍스처로 샘플 → 3단으로 끊어 광원에 붙는 빛 고리가 된다. 창은 가구가 사는 칸만, 전기가 있을 때만 켜진다(없으면 드문 등잔빛).
- 색 연산은 전부 sRGB에서 한다(호환 렌더러는 unshaded 출력을 그대로 내보냄) → `render.json`의 색이 화면에 그대로 나온다.

### Sandbox 인자
`city=<preset> seed=<n> tod=<0..1> angle=<0..3> cut=<-1|n> zoom=<단계 0..2> pan=<x,y[,높이]> speed=<배속> state=<to_dict JSON> power=<0|1|2> hud=0`
시험용: `wave=<프레임>`(첫 전기) `plane=1` `sitedone=<프레임>`(공사 완료) `apitest=1` `perf=1` `save_state=<경로>` `dump_atlas=<경로>` `r:<render.json 경로>=<값>`(예 `r:outline.enabled=false`).
키: Q/E 회전, R/F 층, 휠·+/- 줌, T 시간(Shift+T 실시간), 1-6 프리셋, N 다음 seed, P 전기, L 비행기, Z 구획.

## 2. 콘텐츠 추가법 (뷰 코드 수정 없음)

- **자재**: `visuals.json > materials`에 `"<id>": { "ramp": [밝음→어두움 4색], "pattern": planks|corrugated|brick|concrete|patch, "accent": 얼룩/녹색, "roof": [2색], "frames": [창틀 키 a|b|c|d], "cage": 0|1 }`. 없는 자재는 `_default`.
- **업종·시설·주거 외형**: `visuals.json > types`에 `"<id>": { ... }`. 덮어쓰는 순서는 `_default_<kind>` ← `_group_<group>`(사업체) ← `<id>`.
  - `form`: box(방) / open(텃밭·수조·우물·고물터, `plot`으로 내용 지정) / shed(좌판·발전기) / tank / loft / shrine
  - `window`: none|small|std|wide|cage|shop|shutter|slit, `awning`: 색 또는 ""
  - `sign_style`: neon|paint|lantern|none, `sign_color`: 네온 이름 또는 #색. 글자는 `businesses.json`/`facilities.json`의 `sign`에서 온다.
  - `interior` / `floor`: 층 컷의 가구 묶음과 바닥재. `fx`: steam|smoke|incense|sparks, `chimney`: 옥상 굴뚝, `glow`: 가게 앞 빛 색, `roof`: 꼭대기일 때 얹힐 것의 가중치.
  - 모르는 id는 기본 상자 + 기본 창으로 그려진다(시뮬의 `greenhouse`가 그렇게 나오는 것을 확인).
- **새 창·소품·가구 그림**은 `PixelAtlas.gd`에 타일을 하나 더 그리고(`_begin("이름")`), `CityMesher.gd`의 해당 묶음에서 쓴다 — 이건 코드다.
- **시간대 색**: `render.json > tod.keys`(하늘 3색·연무·빛 3톤·실루엣 2색·밤 세기·창 켜짐 비율).

## 4. 성능 (가장 빽빽한 경우)

| day30_neon_vice | 759 | 16 | 20,510 | 35,604 | 4,732 |

- 층당 메시 1개 + 지면 + 하늘 + 외곽선 + 사람 + 입자. 재질 1개(아틀라스 1장).
- 소프트웨어 GL에서 잰 값이라 프레임 시간은 판단하지 않았다. 프래그먼트 쪽 비용은 그림자 DDA(최대 28회 텍스처 읽기)와 3D 텍스처 1회 — 내부 해상도가 270×480이라 가벼울 것으로 보지만 **저사양 폰 웹에서는 미검증**.
- 전체 재생성(900셀)은 GDScript로 한 번에 한다. 측정은 안 했다. `cell_changed`는 3개 층만 다시 짓는다.
- Web 내보내기: `--export-release "Web"` 성공(pck 5.9MB, 대부분 한자 폰트). **브라우저에서 실제 실행은 확인하지 못했다.**

## 5. 내가 임의로 정한 것 (승인 요청)

번호마다 이유를 적었다. 고르기 쉬운 것은 선택지를 붙였다.

1. **한 층 = 8px, 칸 반폭 = 8px**(층 높이 0.8165). 이유: 벽 한 면이 화면에서 정사각 8×8이 되어 텍셀이 픽셀에 정확히 맞는다.
2. **줌 단계 ×1.25 / ×2 / ×4, 기본 ×1.25.** 디렉터 지시(부지가 화면 폭의 ~90%)를 맞추려고 ×1 대신 ×1.25를 넣었다. 대가: ×1.25에서는 텍셀 1.6개가 1픽셀이라 창틀 굵기가 살짝 들쭉날쭉하다. 선택지 — (1) 지금대로 (2) ×1을 다시 넣어 4단 (3) 기본을 ×2로 하고 패닝 전제.
3. **고도 30° 고정, 층 컷에서도 같음.** 이유: 2:1 계단 유지. `pixel.cut_elevation_deg`로 바꿀 수 있다.
4. **그림자·빛을 전부 셰이더에서 가짜로**(높이맵 DDA + 복셀 빛). 이유: 호환 렌더러·모바일 웹에서 광원 수 걱정이 없고, 저해상도에서 그림자 맵보다 또렷하다. 대가: 돌출부·소품은 그림자를 던지지 않는다.
5. **해는 낮 동안 방위 −58°→118°로 돈다.** 아침엔 왼쪽 벽, 황혼엔 오른쪽 벽이 빛을 받는다. 이유: 낮과 황혼 화면이 톤만이 아니라 형태로도 달라 보이게.
6. **외곽선은 깊이 차가 큰 곳에만 옅게**(세기 0.22). 세게 걸면 잡동사니마다 검은 점이 생겨 지저분해졌다. 선택지 — (1) 지금 (2) 끔 (3) 더 진하게.
7. **창틀 색을 자재에 묶음**(`materials.*.frames`). 칸마다 무작위로 두면 덩어리가 조각보처럼 보였다.
8. **간판 글자는 벽면을 따라 기울어진다**(아이소 픽셀아트 관례). ×2에서는 겨우 읽히고 ×4에서 또렷하다. 선택지 — (1) 지금 (2) 글자만 화면에 똑바로 세우기(읽기 쉽지만 판에서 살짝 삐져나옴).
9. **간판은 사업체당 하나, 크기 4종**(큰 세로 돌출 ~20%, 작은 돌출, 문 옆 작은 판, 문 위 가로판). 같은 글자가 2칸 안에 이미 있으면 작은 판이거나 생략. 줄지은 좌판은 줄의 첫 칸에만 팻말.
10. **밤 빛은 3단으로 딱 끊는다**(디더 없음), 반경을 줄였다. 디렉터 지시("빛은 광원에 붙을 것") 반영. `shade.light_dither`를 1로 올리면 예전처럼 번진다.
11. **팔레트 양자화는 끔.** 화면 붙이기 셰이더에 옵션(`post.quantize`)만 넣어 두었고 **켜서 비교해 보지는 못했다**(시간 부족). 선택지 — (1) 끈 채로 둠 (2) 다음 라운드에 48~64색 팔레트로 시험.
12. **층 컷의 벽은 전부 낮게**(5텍셀), 자른 단면은 어두운 보라. 뒤쪽 벽만 높이는 심즈식은 계산상 고도 30°에서 뒤 칸 바닥을 통째로 가려서(벽 0.82 높이 → 1.4칸 가림) 시도하지 않았다.
13. **사람은 뷰가 지어낸 연출**이다. 가구 수 × 0.11명, 시간대별 비율(새벽 4시 5%, 황혼 옥상 최대, 오락·음성 업종이 있으면 밤 골목 유지). 시뮬 상태와 1:1이 아니다.
14. **대문은 +y 변 가운데**, 대기 가구는 그 앞 보도에 모인다. 표석 글자는 「寨城」.
15. **배경 능선은 사자산 모양**으로 그렸다. 스카이라인은 방향마다 다르지 않고 회전하면 옆으로 흐른다.
16. **FakeCity의 분포·확률 전부**(프리셋별 자재·업종·높이·마당·골목·대기 가구 수). 아트 판정용 가짜이며 게임 수치가 아니다.
17. **상자가 아닌 칸**(텃밭·좌판·물탱크·비둘기장·사당·공사 중)은 이웃 벽을 가리지 않는 것으로 친다. 시뮬이 좌판 위에 방을 쌓으면 방이 기둥 위에 뜬 것처럼 보인다.
18. **한자 폰트 Fusion Pixel 12px(zh_hk, OFL) 전체를 넣음**(7.3MB). 이유: 새 `sign` 글자가 와도 코드 수정 없이 나오게. 줄이려면 쓰는 글자만 추리면 된다.
19. `ARCHITECTURE.md`에 없는 것: `pick()` 결과에 `face` `adjacent` `in_grid` 키를 더했다. `pan_by(화면 변위)` `project_world(Vector3)`를 공개 함수로 뒀다.

## 6. 알려진 약점

- ×1.25 기본 줌에서 잡동사니가 여전히 빽빽하다. 덩어리는 읽히지만 "깨끗한 덩어리"는 ×2에서 더 잘 산다.
- ×4에서 벽 텍셀은 2px인데 사람 스프라이트는 1px라 밀도가 섞인다.
- 쪽방(cage) 실내의 철망 침대가 회색 격자로만 보여 층 컷에서 단조롭다.
- 다리·계단은 한 번 정해지면 다른 층의 셀이 바뀌어도 그 층을 다시 지을 때까지 남는다.
- 사람은 벽을 뚫고 직선으로 걷는다(같은 높이의 옆 칸으로). 계단·문을 따라가지 않는다.
- 비행기 본체는 화면에 잘 안 들어온다(그림자와 흔들림은 보인다).
- 지면 가장자리 디더는 화면에 고정이라 팬할 때 무늬가 흐른다.
- 입력 처리, 발전기 떨림, 깜빡임류는 정지 화면으로는 검증할 수 없었다.
