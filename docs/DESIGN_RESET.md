# 구룡성채 — Anno 기반 전면 재기획 미션 및 설계 제안

버전: v0.3 / 작성 기준: 2026-11-11 / 수신: 기존 프로젝트를 개발 중인 AI

이 문서는 사용자와의 최신 대화를 독립적으로 전달하는 재기획 브리프다. 기존 프로젝트 파일이나 실행 중인 빌드를 직접 검사한 결과가 아니다. 실제 구현 상태는 수신 AI가 확인해야 한다. 문서 안의 경로는 생성·정비할 권장 경로이며, 해당 파일이 이미 존재한다는 뜻이 아니다.

## 0. 가장 먼저 읽을 지시: 기존 설계에 맞춰 해석하지 말 것

너의 미션은 기존 ‘성채 분재’ 게임에 기능 몇 개를 덧붙이는 것이 아니다. 게임의 성장·경제·건축 체계를 Anno 1800을 중심으로 다시 설계하는 것이다. 최신 사용자 결정에 맞지 않는 기존 설계는 교체하라. 이미 만든 코드와 문서에 대한 매몰비용을 새 기획의 제약으로 삼지 마라.

사용자는 완성된 규칙의 단순 구현자가 아니라, 적극적으로 조사하고 설계하고 검증하는 공동 디렉터를 원한다. 이 문서보다 좋은 해결책을 제안하고 실제로 구현할 재량이 있다. 다만 확정한 사용자 선택을 몰래 바꾸거나, 아직 제안인 것을 사용자 결정으로 기록하지 마라.

게임의 새 한 문장:

> 제한된 사각 부지에 주거와 산업, 공급시설을 직접 배치하고, 다섯 계층의 주민 수요와 노동력을 관리하며, 외부 탐험에서 가져온 자재로 자기만의 입체 성채를 완성하는 모바일 도시경제 게임.

플레이어가 “이거 Anno식 수요·계층·생산·무역 구조네”라고 느낄 정도로 기본 체계를 명확히 차용한다. 그 위에 구룡성채의 입체 공간, 건축자재 선택, 주변 탐험, 짧은 모바일 접속 경험을 결합한다. 차별화를 위해 검증된 경제 문법을 불필요하게 뒤틀지 마라.

## 1. 결정 우선순위와 AI의 자율성

우선순위: 사용자의 이후 최신 발언 > 이 문서의 [확정] > 실제로 검증·승인된 후속 결정 > 이 문서의 [제안] > 이전 방향서·GDD·기존 구현.

각 설계 항목에는 다음 상태를 붙여라.

- **[확정]** 사용자가 명시적으로 선택. 구현 우선 기준. 변경이 더 좋다고 판단하면 근거와 대안을 제시하되 조용히 대체하지 않는다.
- **[제안]** 이 문서가 제안한 기본안. AI가 별도 승인 없이 개선·대체하고 이유를 기록할 수 있다.
- **[실험값]** 프로토타입과 시뮬레이션을 위한 초기 수치. 결과와 피드백으로 자유롭게 조정한다.
- **[보류]** 결정되지 않은 사항. 진행에 필요한 가역적 기본안은 AI가 선택하고 가정으로 표시한다.

확정 수치도 영구 불변이라는 의미는 아니다. 80%나 4-8-12-8-6 역시 데이터로 저장하고 실험 브랜치에서 대안을 비교할 수 있다. 다만 기본 빌드의 변경과 사용자 결정 변경은 구분하라.

자율적으로 할 일: Anno 추가 조사, 경제 설계, 콘텐츠 작성, 수요표·생산식 작성, UI 설계, 데이터 구조 정비, 밸런스 실험, 기존 코드 재사용 여부 판단, 가역적 리팩터링, 테스트, 프로토타입 제작. 이미 정해진 질문을 반복해서 진행을 멈추지 마라.

사용자 판단이 필요한 일: 핵심 경험을 바꾸는 선택, 확정 규칙의 변경, 큰 외부 비용이나 외부 공개·배포. 재량은 외부 과금·계정 작업·유료 자산 구매·타인 연락·배포의 포괄 허가가 아니다.

공동 디렉터로서 ‘기획이 부족해서 구현할 수 없다’고 멈추지 말고, 합리적 가정을 두어 비교 가능한 결과를 만들어라. 변경 이유, 장점, 비용, 검증 결과를 짧게 남겨라.

## 3. Anno 1800 벤치마크를 수행하는 방법

Anno 1800 기본 게임, Old World를 중심 참조로 삼아라. DLC, 후속작 Anno 117, 이전 작품의 규칙을 뒤섞지 마라. 개발 초기 블로그는 설계 의도를 보여주지만 출시된 최종 규칙을 모두 보증하지 않으므로 교차 확인한다.

### 3.1 이미 확인한 설계 원리

| 주제 | Anno 1800에서 확인되는 원리 | 구룡성채 적용 |
|---|---|---|
| 주민 성장 | 수요 충족과 주민 단계가 신규 생산·건물 접근을 이끎 [S1] | 경제 진행의 중심으로 차용 |
| 노동력 | 계층별 노동력, 시설별 계층 요구, 승급 시 하위 노동력 보충 필요 [S2,S3] | 계층 공존과 승급의 기회비용 차용 |
| 생산·창고 | 재료를 가공하고 섬 단위 재고를 공유, 생산 물류와 창고 병목 존재 [S4] | 공유 재고·가공은 차용, 복잡한 경로·하역은 단순화 |
| 시장 | 기본 시장은 특정 계층의 공공서비스이며 모든 소비재의 물리적 유통 허브는 아님 [S5] | 우리 시장은 취급등급+범위로 소비재 접근을 제한하는 별도 변형 |
| 전기 | 운영 중 발전소의 도달 범위와 산업 활성화·생산성 증가가 핵심 [S6,S7] | 인구·계층·시설별 총수요를 따지는 용량 체계로 변형 |
| 무역 회계 | 일반 플레이의 지속 운영수지와 무역 거래에 따른 보유현금 변화를 구분 [S8,S9] | 하나의 금고, 구분된 운영·무역·건설 내역 |
| 원정 | 준비·전문가·사건·위험·보상을 가진 외부 활동 [S10] | 기본 건축자재의 반복 탐방과 장거리 특수자재 확보로 재설계 |

시장·전력·탐험의 변형을 ‘Anno와 동일’이라고 설명하지 마라. 특히 Anno 원정을 5분짜리 반복 기본자재 채집 시스템이라고 오해하지 않는다. 그것은 사용자의 구룡성채 설계다.

### 3.2 반드시 더 조사해서 산출할 것

`research/ANNO1800_BENCHMARK.md`에 다음을 작성하라: 주거 수요·입주·승급 조건, 기본/행복/선택 수요의 차이, 소비량 산정 기준, 계층별 노동력, 해금 인구 판정, 창고·생산·물류, 수입과 유지비, 무역 거래 시점과 재고 보호, 전력, 소방·의료·사건, 원정, 통계 UI.

각 항목은 ‘원작 규칙 / 출처·열람일 / 우리 적용 / 의도적 차이 / 미확인 사항’으로 정리한다. 실제 플레이 또는 영상으로 확인할 수 있으면 활용하되 보지 않은 것을 플레이 검증으로 쓰지 마라. 출처가 없는 세부 수치는 추정으로 표시한다.

‘Anno와 비슷하게’라는 추상적 지시로 끝내지 말고, 사용자 행동에서 확인할 수 있게 하라: 주거를 눌러 부족 수요 확인 → 생산량과 소비량 비교 → 작업장 추가 또는 수입 계약 → 충족률 개선 → 비용을 내고 승급 → 노동력 구성 변화 → 새 공급 문제 해결.

## 4. 핵심 플레이 순환

### 4.1 도시 내부

주거 구역 지정 → 초기 주민 입주 → 계층별 노동력 확보 → 시장·작업장·물 공급 배치 → 소비재 생산 또는 정기 수입 → 생활·승급 조건 충족 → 자재 선택·수동 승급 → 인구·세수·노동력 변화 → 신규 시설·상품·탐험·계약 해금 → 공간과 공급망 재설계.

### 4.2 도시 외부

다음 건축에 필요한 자재 확인 → 월드맵에서 목적지 선택 → 탐험대·준비물 배정 → 실시간 경과 → 결과 확인·보상 수령 → 목재/철제/콘크리트 중 선택해 주거 승급 → 다른 외관의 성채 형성 → 새로운 목적지와 희귀 재료 수요.

### 4.3 중장기 판단

전부 고급화하지 않는다. 필요한 계층을 유지하고 생산·수출·수입의 균형을 잡는다. 저급 시설 여러 개로 면적을 쓸지, 비싸지만 면적을 절약하는 외부 공급을 쓸지, 자재를 모아 고급 자체 시설로 전환할지 결정한다. 재료 탐험의 방향이 도시 외관에 누적된다.

## 5. 확정 규칙 전체 목록

### 5.1 주거·인구

- [확정] 주거는 플레이어가 구역으로 지정한다. 주민의 생활·외관 변화는 해당 구역 안에서 일어난다.
- [확정] 총 5계층. 한 기본 주거 단위의 최대 정원은 **4 → 8 → 12 → 8 → 6명**.
- [확정] 계층은 특정 직업에 귀속되지 않는다. 생활·서비스 조건을 충족하고 승급하면 상급 시민이 된다. 각 계층은 해당 계층이 수행 가능한 여러 직장에 취업한다.
- [확정] 하위 계층이 필요한 산업은 후반에도 남는다. 상위 시민이 하위 노동력을 자동 대체하지 않는다.
- [확정] 비취업 생활인구는 최하위 계층에만 존재한다. 초기 기준은 4명 중 1명. 다른 계층에는 동일 비율을 적용하지 않는다.
- [확정] 승급 조건이 충족되면 표시하고, 플레이어가 비용·자재를 제공해 승인해야 승급한다.
- [확정] 공급 불만·쇠퇴에는 충분한 유예를 둔다.

### 5.2 공간

- [확정] 시장·작업장·기반시설·랜드마크는 플레이어가 직접 선택·배치한다.
- [확정] 한 층의 점유율 80%에서 다음 층이 열린다.
- [확정] 해금된 상층의 아래가 비어 있어도 건설·구역 지정 가능. 필요한 지지대가 즉시 생긴다.
- [확정] 상층 건축 뒤 아래 건물이 축소·삭제돼도 골조가 남는다.
- [확정] 계단·복도·다리는 자동 표현. 서비스 접근성은 거리·층수로 계산. 복잡한 경로 연결성 설계를 기본 플레이로 되돌리지 않는다.
- [보류] 주거의 논리적 합병. 연속된 주거가 시각적으로 연결된 복합건축물처럼 보이는 것은 지향한다.

### 5.3 경제·공급

- [확정] 생산 체인은 중간 깊이. 초기부터 긴 다단계 가공 사슬을 강제하지 않는다.
- [확정] 시장은 운영 인력·취급 자격·범위를 요구한다. 재고 없이는 판매·공급이 없다.
- [확정] 시장 범위 안에 주민이 늘어도 시장별 유통량 상한은 두지 않는다. 도시 전체 소비량은 증가한다.
- [확정] 필수 수요와 대체 가능한 선택 수요를 혼합한다.
- [확정] 교역은 정기 계약 중심. 추이를 보고 계약을 관리한다. 거래 현금은 도시 금고에 반영된다.
- [확정] 물·전기는 주민 수와 계층 구성에 따른 수요, 시설 수요를 합산하고 공급량을 충족해야 한다.
- [확정] 전력이 필요한 시설이 존재한다. 전기는 새 생활·산업을 여는 발전 단계다.
- [확정] 외부 수도·전력 연결은 초급 자체 설비보다 공급력이 좋고 공간을 절약하지만, 비용 효율이 낮은 중간 보충 선택지다. 자체 상급 시설의 영구 상위호환이 아니다.

### 5.4 자재·외관·탐험

- [확정] 최하급 주거는 낡은 판자와 양철 중심의 공통 외관.
- [확정] 이후 각 승급마다 목재·철제·콘크리트 중 한 종류를 선택해 제공한다. 같은 승급에서 세 종류의 요구 수량은 동일하다.
- [확정] 선택한 자재가 주거의 주된 외관을 결정한다. 보유만으로 자동 변경하거나 랜덤으로 정하지 않는다.
- [확정] 자재 확보의 핵심은 탐험이다. 성채 중심의 주변 지형이 보이는 월드맵에서 대상지를 선택해 탐험대를 보낸다.
- [확정] 탐험지마다 주로 얻는 자재가 다르다. 근거리 탐험은 실제 5~10분 뒤 결과 확인·수령하는 반복 행동이 된다.
- [확정] 원거리의 자재·특수자재는 실제 수시간이 걸리는 탐험으로 확보한다.
- [확정] 짧은 접속의 수확감과 나중에 돌아와 결과를 확인하는 기대감을 모두 추구한다.

## 6. 주민 계층과 노동력 상세 제안

아래 이름은 [제안]이다. 직업 이름을 계층 이름으로 고정하지 마라. 취업이 승급의 유일 조건이거나 의사가 돼야 4계층이 되는 구조를 만들지 않는다.

| ID | 임시 명칭 | 정원[확정] | 비취업 인구 | 경제적 역할 제안 |
|---|---|---:|---|---|
| T1 | 정착민 | 4 | 25% 초기 기준 | 초기 노동력, 저가 생필품 소비 |
| T2 | 생활민 | 8 | 없음 | 다수의 식품·생활품 가공, 기본 서비스 |
| T3 | 중산 시민 | 12 | 없음 | 가장 높은 인구 밀도, 기술·상업 노동력 |
| T4 | 상급 시민 | 8 | 없음 | 공간을 더 쓰는 고소득 주거, 전문 서비스 |
| T5 | 특급 시민 | 6 | 없음 | 낮은 밀도·높은 소비·높은 세수·상위 사업 인력 |

계층별 노동력을 도시 전체 풀로 관리하는 것을 [제안]한다. 실시간 개별 출퇴근 길찾기와 노동력 계산을 연결하지 않는다. 화면의 주민은 해당 풀의 상태를 시각화한다. 건물은 `workforceRequirements`로 한 개 또는 여러 계층을 요구할 수 있지만 초기에는 한 계층 위주로 이해하기 쉽게 한다.

T1 노동력은 `actualResidents × 0.75`를 기본안으로 한다. 부분 입주에서 소수 노동력을 허용할지 도시 합계 후 정수화할지 문서화한다. 건물마다 반올림해 입주·퇴거로 노동력을 복제하는 오류를 피한다. T2 이상은 기본적으로 실제 인구가 노동력 풀에 기여한다. ‘비취업 인구 없음’과 ‘일자리 부족으로 미배정 노동력 존재’는 다른 개념이다. 사용자의 선택을 모든 시민의 강제 완전고용으로 오해하지 않는다.

탐험대에 시민 노동력을 차출하는 경우 별도 차감해야 한다. 초기 [제안]은 인구 풀과 분리된 탐험대 슬롯이며, 실제 인력을 차출하는 방식은 도시경제에 주는 영향을 비교한 뒤 선택한다.

### 6.1 정원 감소를 반드시 처리할 것

T3 정원 12 → T4 정원 8 → T5 정원 6에서 기존 주민이 사라지는 버그나 설명 없는 인구 손실을 만들지 마라.

[제안] 기존 계층의 남는 주민은 우선 같은 계층의 빈 주거로 자동 재배치. 자리가 없으면 승급 확인창에 ‘4명에게 이주 공간 필요’를 표시하고, 기본 정책에서는 대기시킨다. 임시 숙소·도시 외부 이주 등 다른 선택은 AI가 제안할 수 있다. 이주되는 주민은 새 계층 노동력이 되지 않으며 옮겨간 기존 계층의 인구·노동력으로 남는다.

예: T3 12명이 사는 주거를 T4로 올림. 8명은 T4로 전환하고 4명은 기존 T3 빈집에 이동. 도시 총인구는 유지, 노동력은 T3 -8/T4 +8. 빈집이 없어서 이주를 허용하면 총인구가 줄어드는 경우도 있을 수 있으나 사전에 명시한다. 이 예는 제안 정책이며 사용자가 인구 이전 방식까지 확정한 것은 아니다.

T1→T2처럼 정원이 늘 때도 빈자리까지 즉시 인구로 생성하지 않는다. 기존 주민 전환과 이후 이주 유입을 구분한다. 필요한 경우 완전 입주가 승급의 조건인지 AI가 연구·선택하라.

### 6.2 승급 화면의 필수 정보

충족/부족 수요, 다음 단계 정원, 예상 세수, 노동력 전환, 이주 필요 인원, 다음 단계 예상 물·전기·상품 소비, 돈·자재 비용, 선택 가능한 재료와 외관 미리보기. 실제 입주가 완료됐을 때의 전망과 즉시 변화는 분리한다. 같은 비용으로 외관을 비교할 수 있어야 한다.

## 7. 수요·행복·해금 설계

수요를 세 그룹으로 분리하는 것을 [제안]한다: 계층 유지의 기본 수요, 승급 조건, 선택적 행복·수입 수요. 한 품목이 둘 이상의 효과를 가지는 것은 가능하되 UI에 역할을 설명한다.

필수는 AND, 대체는 OR 또는 N-of-M로 데이터화한다. 예: 깨끗한 물 AND 기본 의류 AND (국수 OR 어묵 OR 채소 식사) AND (찻집 OR 마작방). 공통 재고에서 대체 식품을 모두 중복 소비하지 않도록 선택 우선순위가 필요하다. 재고 변화마다 매 틱 대체품을 바꿔 공급률이 흔들리는 현상은 유예·선호 고정으로 완화한다.

### 7.1 5계층 콘텐츠 출발안 [제안, 사용자 확정 아님]

| 계층 | 기본 생활 후보 | 다음 발전에 필요한 후보 | 행복·수입 후보 |
|---|---|---|---|
| T1 | 저가 식량, 식수, 기초 시장 | 기본 의류, 양초, 안정적 기초 공급 | 저가 술, 작은 사당 |
| T2 | 안정된 식량·물·의류·조명 | 위생, 의료 접근, 가공식품 선택군 | 차, 마작, 목욕 |
| T3 | 다양한 식품, 위생·의료, 전기 접근 | 개선된 주거 서비스, 전문 시설, 고급 생활품 일부 | 라디오, 공연, 정원, 맥주 |
| T4 | 높은 물·전력 사용, 양질의 식품·의류, 고급 서비스 | 고급 소비군·도시 시설 조건 | 가전, 고급 주류, 전망 공간 |
| T5 | 안정적인 고급품·전문 서비스 공급 | 최고 단계이므로 승급 없음 | 복수 사치 선택군, 명소, 특별 시설 |

‘매 계층 모든 과거 물품을 계속 추가’하면 재고와 체인이 과도하게 늘어난다. 대체·졸업 품목과 계속 필요한 품목을 의도적으로 설계하라. 촛불→전기 전환 시 양초 소비가 언제 줄고 언제 다시 필요한지도 명시하라. 가스는 요리·특정 업종과 연결할 수 있지만 전기와 같은 새 용량 시스템으로 무조건 늘릴 필요는 없다.

각 욕구는 충족률에 따른 인구/세수/행복/승급 효과를 데이터로 둔다. 상급 수요 해금과 동시에 모든 기존 주거가 급락하는 함정을 피하고 적응 기간을 제공한다. 행복은 모든 필수품을 대신하는 만능 수치가 아니다.

해금은 계층별 실제 인구, 시설 존재, 탐험 발견, 인프라 상태 등의 조합. 승급에 필요한 물품을 생산하는 시설이 바로 그 승급 이후에만 열리는 순환 잠금을 검사한다. 첫 주민을 만들 최소 수입·시드·대체 공급을 제공해야 한다. 한 번 얻은 해금을 인구 감소 때 회수할지, 건설은 유지하고 신규 건설만 제한할지는 [보류]이며 영구 해금 기본안을 권한다.

## 8. 시장과 서비스 범위

[제안 기본식] 주거 r이 상품 g에 접근하려면: 운영 가능한 시장 중 하나가 r의 범위를 커버하고, 해당 시장이 g를 취급할 수 있고, 도시 공유 재고에서 할당량을 받을 수 있어야 한다.

시장별 재고·수용 인구·하역 속도·배달 물량은 기본 모델에 넣지 않는다. 범위 안의 사람이 늘면 도시 총소비만 증가한다. 범위가 겹쳐도 소비와 보너스를 중복 적용하지 않는다. 같은 시장 등급이 여러 개 있어도 상위 등급 취급 자격이 자동 생성되지 않는다.

거리 [실험안]: `distance = abs(dx) + abs(dy) + verticalWeight × abs(dz)`; 별도 `maxFloorDelta`로 층간 무제한 공급 방지. 건물 크기가 여러 칸이면 가장 가까운 서비스 접점 또는 명시한 중심점 중 하나로 통일. 회전한 카메라 좌표가 계산에 영향을 주지 않아야 한다. 범위의 경계와 위·아래층 영향은 배치 전에 보인다. 정확한 거리 함수와 계수는 AI가 비교·선정한다.

시장 등급 초기안: 잡동사니 시장 → 생활 시장 → 종합 시장 → 고급 상업시설. 상위 시장은 하위 상품도 취급하는 것을 기본안으로 하되 운영비가 더 든다. 단계별 인력 등급, 범위, 소비전력, 취급 태그를 별도 데이터로 둔다. 공공시설 노동력이 모자랄 때 범위를 계속 깜빡이게 하지 말고, 가동 여부·최소 인력·부분 서비스 규칙을 정해 안정화한다.

## 9. 생산·공유 재고·수입

중간 깊이의 체인을 기본으로 하라. 일부 원료는 외부 조달하고 성채 내부에서 가공한다. 좁은 부지 안에서 모든 농업·광업·중공업 원료를 생산할 필요가 없다.

### 9.1 콘텐츠 후보 [제안]

| 시설 | 입력 후보 | 출력 후보 | 배치·경제적 의미 |
|---|---|---|---|
| 고물 작업장 | 탐험 회수품 | 재사용 부품·기초 자재 | 초기 산업, 탐험과 연결 |
| 제면소 | 밀가루·물 | 국수 | 기본 식품, 잉여 수출 |
| 어묵 작업장 | 어육·물 | 어묵 | 대체 식품, 명물 가능성 |
| 봉제 작업장 | 원단 | 기본 의류 | 승급 필수 공급 후보 |
| 양초 작업장 | 왁스류 | 양초 | 전력 이전 생활, 이후 틈새 수요 |
| 비누 작업장 | 유지류 | 비누 | 위생 소비재 후보 |
| 전파사·수리소 | 부품·전기 | 수리품·생활 전자제품 | 중급 산업과 네온 풍경 |
| 고급 조립소 | 정밀 부품·전기 | 고급 생활제품 | 상급 노동·수출 |
| 찻집·마작방 | 인력·운영비, 선택적으로 상품 | 범위형 여가 | 공유 소비재와 공공서비스 차이 학습 |

입력·출력 수량, 작업시간, 필요한 계층, 고정 운영비, 가동 운영비, 물·전기 소비, 면적, 소음·위험 태그, 해금은 모두 데이터화. 이름은 구룡성채의 생활감에 맞게 다듬되 목록을 그대로 한 번에 구현할 의무는 없다.

재고 방정식은 생산+수입+탐험수령−주민소비−가공투입−건설소비−수출이다. 모든 항목을 추적 가능하게 한다. 재료가 없는데 생산하거나 잔고가 음수인데 계약이 반복 결제되는 오류를 차단한다.

주민 상품 소비량은 실제 인구·계층·품목별 단위시간 소비로 계산하는 것을 [제안]한다. Anno의 주거 단위 소비 방식과 차이가 있을 수 있으므로 조사 후 의도적 차이로 기록한다. 생산 효율은 인력·원료·필수 유틸리티를 모두 고려하되 같은 부족률을 여러 번 곱해 과도하게 감소시키지 않도록 정의한다.

시장 판매액과 주민 세수를 무심코 이중 수입으로 계산하지 마라. [제안] 내부 소비는 수요 충족을 통해 주민 세수에 반영하고, 외부 수출만 별도 판매대금으로 기록한다. 민간 사업세·직영 서비스 수입을 추가한다면 자금흐름 표를 먼저 작성한다.

## 10. 물·전기와 기반시설 발전

[확정] 총수요는 인구·계층 구성과 시설을 모두 반영한다. 같은 인구라도 상급 계층이 많으면 수요가 달라야 한다.

`residentDemand(u) = Σ(actualPopulation[tier] × perCapitaDemand[tier,u])`

`facilityDemand(u) = Σ(standbyDemand + operatingDemand × activityFactor)`

`supply(u) = Σ(localUtilityOutput) + contractedExternalSupply`

단위는 명시하라. 물은 일관된 ‘물 단위/경제분’, 전기는 ‘공급 용량/부하’ 등으로 처리할 수 있다. 물 저장량, 물 생산속도, 전력 용량, 에너지 재고를 같은 변수로 섞지 않는다. 빗물의 생산 변동이나 배터리 등은 별도 확장이며 처음부터 날씨·저장장치를 전부 만들 필요는 없다.

### 10.1 발전 단계

| 단계 | 물 후보 | 전력 후보 | 플레이 의미 |
|---|---|---|---|
| 초기 | 빗물받이·집수통 | 무전력 생활, 이후 소규모 풍력·소형 발전기 | 낮은 건설비, 낮은 공급, 공간 많이 필요 |
| 중간 자체 | 지하수·급수탑·정수 | 개선된 발전 설비 | 노동력·자재 투자로 효율 개선 |
| 외부 보충 | 외부 수도 연결 | 외부 전력망 연결 | 적은 공간, 비교적 큰 공급, 비싼 운영비 |
| 상급 자체 | 통합 정수·급수시설 | 상급 자체 발전·배전시설 | 큰 선행 투자, 장기 운영 효율 |

외부 연결은 월등한 공짜 편법이 아니다. 안정적인 중간 보충 선택지가 되게 한다. 단속·차단·조직 갈등은 추가 제안 가능하지만 이것만으로 균형을 맞추지 마라. 공간당 공급량과 단위 공급비용의 차이만으로 먼저 선택 이유를 만들어라. 불법 연결은 게임 안의 계약·설비로 추상화한다.

전력은 ‘없으면 정지하는 시설’과 ‘있으면 더 효율적인 시설’을 구분할 수 있다. [제안] 초기에는 필수/비필수 구분을 명료하게 하고, 산업 생산성 보너스는 별도 데이터로 둔다. 전력 수요를 계산하는 우리 모델을 Anno의 단순 범위 전력과 혼동하지 않는다.

필수 서비스 인력·전력이 부족하면 배분 우선순위를 정한다. [제안] 식수·기본 생활·안전 → 필수 식품 생산 → 일반 산업 → 사치·경관. 플레이어가 바꿀 수 있는 수준은 AI가 UX를 검증한다. 펌프가 전기를 만들 시설의 물을 기다리고 발전기가 펌프 물을 기다리는 완전 정지 상태에는 저급 독립 공급이나 비상 운영으로 복구 경로가 있어야 한다.

## 11. 층 해금·골조·건축

### 11.1 80% 규칙의 구현 제안

부지의 유효 가로×세로 면적은 아직 확정하지 않았다. 예전 12×12×8은 기본값으로 자동 승계하지 말고 모바일 가독성·공간 제약·30일 성장 규모로 결정한다.

해금은 `occupiedFunctionalCells / eligibleFloorCells >= 0.8`의 기본안을 사용한다. 무엇이 functional인지 콘텐츠 태그로 정의한다. 완성된 주거·작업장·운영 가능한 공간이 점유에 포함되는 것을 권한다. 초안·무료 구획 칠하기만으로 무한 층 해금을 얻지 않게 한다. 텃밭·정원·마당도 실제 사용 공간이라면 포함할 수 있다. 지지대만 있는 칸은 자동 점유로 간주하지 않는 안을 권한다.

해금은 층마다 순차적으로 적용하고 이미 열린 층은 아래 점유율이 내려가도 닫지 않는 기본안을 권한다. 사용자가 정한 80%는 유지하되 점유 정의·영구 해금은 AI 제안임을 기록한다.

### 11.2 지지대와 구조 보존

[확정] 아래가 빈 곳에 상층 건물·구역을 지정하면 지지대가 즉시 생성된다. 필요한 경우 지면 또는 기존 골조까지 연속 지지한다. 실제 구조공학 계산은 요구하지 않는다.

[제안] 지지 구조를 방의 용도와 분리한 structural state로 저장. 지지대는 이후 아래 공간 사용을 불필요하게 막지 않는 시각·구조 층으로 취급한다. 추가 비용을 청구할지는 실험 사항이며, 청구한다면 명령 전에 총액을 보여주고 자원이 부족하면 명령 전체를 원자적으로 취소한다. 건물만 생성되고 지지대가 실패하는 상태는 금지.

아래 시설 철거 후 상층은 유지된다. 건물 실내·외장을 바꾸는 작업과 지지 골조 자체를 없애는 작업을 UI에서 구분한다. 자동 지지대로 건축 자유는 확보하되, 돌출과 빈틈이 눈에 보이게 하여 단순한 꽉 찬 상자만 나오지 않게 한다.

### 11.3 주거 연결

초기에는 각 주거 ID와 경제 상태를 유지하면서 인접한 같은 재료·유사 등급 주거의 외벽, 지붕선, 공용 통로, 계단을 시각적으로 연결한다. 다른 등급·재료 사이에는 경계와 증축 흔적을 남긴다. 경제적 병합은 보류. 선택 영역과 UI에서 주거 한 단위를 명확히 가리킬 수 있어야 한다. 외관 연결 때문에 업그레이드 대상·원가·인구가 불명확해지면 안 된다.

## 12. 건축자재 선택이 만드는 외관

### 12.1 핵심 규칙

T1 공통 외관을 제외한 각 승급에서 세 종류 중 정확히 한 가지 재료를 선택한다. 전환 단계별 요구량 `Q[fromTier,toTier]`는 다를 수 있지만 동일 전환의 목재/철제/콘크리트 요구 수량은 같아야 한다. 공통 돈·보조자재 비용은 별도로 둘 수 있으나 초기에는 복잡도를 제한하라. 숫자는 실험값이다.

예: T2→T3에 목재 20 OR 철제 20 OR 콘크리트 20 + 공통 건축비. 20은 확정 수치가 아니다. 선택한 재료가 `materialFamily`가 된다. 자재를 보유했다는 이유로 기존 주택이 자동으로 변하지 않는다.

주거 외관은 `tier × materialFamily × location × utilityState × localActivity × stableVariationSeed`로 구성한다. 재료가 메인 외관을, 등급이 품질을, 전력·업종이 생활 디테일을 결정한다. 신규 데이터 로딩 때 랜덤 외관이 매번 바뀌지 않게 한다.

### 12.2 외관 매트릭스 출발안

| 계층 | 목재 | 철제 | 콘크리트 |
|---|---|---|---|
| T1 | 공통: 낡은 판자·양철·수선 흔적 | 동일 | 동일 |
| T2 | 정리된 목조 거처·차양 | 금속 패널·보강 프레임 | 거친 미장·단순 창문 |
| T3 | 촘촘한 목조 복층·발코니 | 모듈 주거·외부 설비 | 밀집 공동주거·공용 발코니 |
| T4 | 공간이 넓어진 목조 주거·테라스 | 정돈된 금속 외장·설비 | 넓은 창·개선된 실내·마감 |
| T5 | 고급 목조·정원과 큰 생활공간 | 고급 금속·유리·첨단 설비 | 고급 콘크리트·절제된 조형 |

재료를 선악·부유함·기술 수준과 동일시하지 마라. 목재도 최상급 주거가 될 수 있다. 네온은 재료가 아니라 전력과 상업·오락 수요가 만드는 층이다. 철제라고 범죄도시가 되지 않는다. 동일 계층의 수용 인구는 재료와 무관하게 사용자 확정값을 따른다.

재료별 화재·유지비 차이는 [보류]. 먼저 세 계열이 같은 경제적 성능에서도 선택할 만큼 매력적인지 검증하라. 효과를 넣더라도 한 자재가 모든 면에서 우월해 외관 선택을 강제하지 않는다. 같은 수량이 같은 확보 시간·가치를 뜻하는 것은 아니므로 탐험 보상까지 함께 밸런싱한다.

재료 변경은 기본적으로 다음 승급에서 가능하다. 최고 단계 재외장 기능은 [제안]이며, 원하는 도시를 나중에 고칠 수 있도록 검토하라. 철거·환불로 재료가 복제되지 않도록 비용·재사용률을 정의한다.

## 13. 탐험은 핵심 성장 시스템이다

탐험을 보조 일일퀘스트나 단순 보상 버튼으로 축소하지 마라. 외관 선택에 필요한 자재를 의도적으로 확보하는 시스템이다. 성채의 경제가 탐험 준비를 돕고, 탐험의 자재·발견이 성채의 다음 단계로 이어져야 한다.

### 13.1 월드맵

성채가 중심에 있고 주변 지형·폐허·거래 거점·먼 지대가 보인다. 초기에는 근거리 대상지 일부를 알고, 더 먼 지역은 조사·도시 발전·탐험 결과로 열린다. 장식 지도 위 메뉴 목록이 아니라 가까움과 멂, 자재 분포를 시각적으로 이해할 수 있어야 한다. 해양 개척을 그대로 복제할 필요는 없다.

| 탐험지 후보 | 주력 자재 | 짧은 설명 | 시간 후보 |
|---|---|---|---|
| 철거된 가구 골목 | 목재 | 문짝·가구·판재 회수 | 5~10분 |
| 폐정비소·고철 야적장 | 철제 | 프레임·패널·금속 회수 | 5~10분 |
| 철거 공사장 | 콘크리트 계열 자재 | 재사용 블록·프리캐스트 부재 | 5~10분 |
| 외곽 창고 지대 | 선택 자재+생활 원료 | 더 큰 물량과 발견 | 중거리, AI 제안 |
| 폐산업 단지 | 철제+특수 부품 | 고급 설비로 연결 | 수시간 |
| 산지 목재 야적장 | 목재+희귀 목재 | 목조 특화 확장 | 수시간 |
| 버려진 대형 건설 현장 | 콘크리트+구조 부재 | 상급 시설·확장용 | 수시간 |
| 옛 발전소·연구 시설 | 특수자재·도면 후보 | 기반시설 발전 | 수시간 |

장소와 시간은 근거리 5~10분/원거리 수시간이라는 확정 범위 안의 제안이다. 콘크리트를 바로 재사용한다는 표현이 거슬리면 자원을 ‘콘크리트 부재’로 정의하라. 작은 벽돌 조각을 주웠는데 상급 콘크리트 건물이 즉시 완성된다는 시각적 부조화는 자원 단위의 추상화로 설명한다.

### 13.2 파견 과정

목적지 카드에 주력 자재, 기본 보장량 또는 범위, 특수 보상 가능성, 왕복 포함 총시간, 준비 비용, 위험, 필요한 능력을 보여준다. 탐험대 선택 → 필요한 준비물과 선택 보급 → 파견 → 진행 → 귀환/결과 확인 가능 → 보상 확인·수령.

‘그레이프밸리의 포도수확’은 사용자가 설명한 기다림 뒤 수령하는 감각을 뜻한다. 해당 게임의 세부 규칙을 확인하지 않고 복제했다고 주장하지 마라.

기본 근거리 탐험은 반복 가능한 자재 공급원으로 설계한다. 필수 기본자재가 매번 무작위로 안 나와 성장이 막히게 하지 마라. [제안] 주력 자재 기본 보장 + 추가량·부가발견 변동. 원거리 탐험은 큰 물량, 특수자재, 새 목적지·계약·인물 발견 등으로 가치가 달라진다.

### 13.3 단기·장기 시간의 균형

짧은 탐험은 플레이 중 한두 차례 결과 확인하는 손맛, 긴 탐험은 외출·수면 뒤 돌아올 기대감을 제공한다. 매 5분 접속이 유일한 최적해가 되지 않게 장기 파견의 시간당 효율과 슬롯 효율을 비교하라. 긴 탐험이 모든 보상을 압도해 짧은 파견이 무의미해지는 것도 피한다.

[제안] 완료 결과는 소멸하지 않고 미수령으로 보관한다. 늦게 확인했다고 탐험대가 추가 피해를 받지 않는다. 기본 탐험은 출발 전에 선택을 끝내고 오프라인 동안 완료할 수 있어야 한다. 사건 선택이 필요한 탐험은 결과를 대기시키고, 야간 즉답을 요구하지 않는다. 사용자는 재접속 동기를 원하지만 늦게 수령하면 자재가 썩는 규칙까지 요구한 것은 아니다.

파견 슬롯 수·대기열·재파견 버튼·자동 반복은 [보류]. 초기 1~2팀으로 시작해 탐험 거점 확장으로 슬롯을 얻는 안을 시뮬레이션하라. 팀 확대가 자재·돈 무한 증식과 강제 클릭을 만들지 않도록 노동·보급·운송·슬롯 비용 중 적절한 제약을 선택하라.

### 13.4 탐험과 도시경제를 연결하는 후보

식품 생산 → 도시 소비 외에 탐험 식량으로 사용. 의류·도구·의료품 → 특정 탐험 준비 선택. 기술계층 성장 → 정밀 회수·장거리 운송 해금. 발견한 거래처 → 정기 수입 계약. 회수한 발전 부품 → 상급 시설 건설. 구출·이주 제안 → 주민·인물 유입. 이것들은 전부 처음부터 의무 구현이 아닌 확장 후보이며 가장 이해하기 쉬운 연결부터 만든다.

기본 생활경제가 탐험 수령 버튼에 매달려 멈추지 않도록 하라. 자재는 건설·승급·확장의 주요 입력, 식량과 생활 소비품은 생산·정기 교역의 주요 입력으로 구분하는 기본안을 권한다. 탐험의 우연한 식량 보상은 보조일 수 있다. 건설자재를 무역으로도 구할 수 있을지는 미확정이나 허용해도 탐험을 무의미하게 만들지 않도록 가격·종류·물량을 설계한다.

### 13.5 발견과 놀라움

반복 파견에는 예측 가능한 목표 수확을, 첫 방문·고난도 탐험에는 새로운 장소·이야기·특별 물품을 배치하라. 수많은 고유 이벤트를 생성하는 것보다 ‘내가 다음에 무엇을 할 수 있는지가 달라지는 발견’을 우선한다. 예: 새 콘크리트 확보처, 오래된 네온 간판, 물탱크 도면, 정기 식량 공급자. 실제 생산을 대체하는 만능 희귀품을 남발하지 않는다.

## 14. 정기 교역과 재정

교역소·창고·출입 거점의 이름과 공간은 구룡성채 맥락으로 제안한다. 플레이어는 계약 상대·상품·수량·주기·가격을 보고 정기 수출입을 운영한다. 자동 재고 기준 매매를 기본 체계로 교체하지 않는다. 최소 재고 보호는 계약 실행의 옵션으로 둘 수 있다.

계약 데이터: 상대 ID, 상품 ID, 수입/수출, 회당 수량, 주기, 회차별 가격, 운송비, 시작/종료, 다음 결제·배송 시각, 최소 보유량, 실패 처리, 일시정지, 변경 적용 시점, 해금 조건.

[제안] 결제와 물품 이전은 거래 완료 때 원자적으로 일어난다. 자금·재고 부족 시 부족량을 표시하고 그 회차를 건너뛰거나 명시된 부분 이행으로 처리한다. 신규 플레이어에게 첫 실패부터 회복 불가능한 벌금을 부과하지 않는다. 신용·선금·위약금은 기본 시스템이 안정된 뒤 제안한다.

월드맵 탐험에서 만난 거래처가 계약 메뉴에 추가되는 연결을 권한다. 원거리 탐험이 기본 계약의 전부를 잠그지는 않게 초기 생존 계약을 제공한다. 외부 공급을 이용한 고급 시민 중심 도시도 가능하지만 돈·계약 공급량·정기 배송 간격이 제약이 된다.

회계는 보유현금/운영수지/실현무역수지/예상계약현금흐름/건설·승급지출로 구분한다. 기간을 표시하고 예상과 실제를 섞지 않는다. 수출 매출과 생산원가를 뺀 이익을 구분하라. 운영비를 이미 뺀 뒤 무역이익 계산에서 다시 차감하는 이중 계산도 금지한다.

예측은 ‘다음 납품까지 식량이 버티는가’, ‘확정 계약을 모두 이행하면 현금이 언제 부족해지는가’, ‘승급하면 수입품 소비가 얼마나 증가하는가’를 알려줘야 한다. 단순 수입 순위가 아니라 추이를 보며 관리하는 재미가 목표다.

## 15. 시간·오프라인·재접속

세 가지 시간을 분리하라: 경제 시뮬레이션 시간, 탐험·계약의 실제 경과시간, 낮밤 시각 연출. 배속·개발도구로 경제를 가속했다고 실제 6시간 탐험의 공개 빌드 타이머가 임의로 완료되면 안 된다. 테스트 모드에서는 모든 시간을 주입 가능한 시계로 통제한다.

탐험 실제 5~10분/수시간은 확정이다. 도시경제와 계약이 실제 시간으로 어느 속도로 진행할지, 오프라인 최대 계산 기간은 [보류]. AI가 1일 여러 번 짧게 접속하는 모바일 경험과 수시간 만에 접속하는 경험을 모두 시뮬레이션하고 기본안을 제시하라.

[제안] 오프라인에서도 생산·소비·정기 계약을 동일한 규칙으로 계산하되, 장기 부재로 인한 파괴적 연쇄 붕괴를 제한하는 보호 구간·자동 감산·유예 정책을 검토한다. 이를 ‘확정된 오프라인 면책’으로 기록하지 않는다. 복귀 요약에는 생산량, 계약 이행, 소비, 부족 발생 시점, 탐험 완료를 보여준다.

실제 시간 이벤트는 `startedAt`, `completesAt`, `lastSettledAt` 등으로 저장한다. 온라인 초당 루프 횟수에 의존하지 않는다. 정기 거래·탐험 완료·저장 시점이 같은 경우 처리 순서를 고정한다. 오프라인을 한 번에 계산한 결과와 작은 시간 단위로 계산한 결과가 허용 오차 안에서 같아야 한다. 여러 완료 보상 수령은 멱등적으로 처리하고 중복 클릭·새로고침으로 복제되지 않게 한다.

기기 시계 변경 대응은 배포 환경에 맞게 정직하게 설명한다. 서버가 없다면 완전한 조작 방지를 보장하지 말고 음수 시간·과도한 도약 방어와 일관된 저장을 우선한다.

## 16. 플레이어 경험과 모바일 UI

기본 화면은 성채다. 건설·주거·경제·탐험·정책을 접근하기 쉽게 배치하되 숫자 대시보드가 도시를 가리지 않게 한다. 구체 메뉴 수와 배치는 AI가 프로토타입으로 결정한다.

필수 흐름:

1. 주거 탭 → 현재 계층/인구/노동력/세수/수요/승급 표시.
2. 부족 수요 탭 → 원인(재고 없음, 시장 범위 밖, 취급등급 부족, 인력 부족, 물·전력 부족) → 생산·계약·시설로 이동.
3. 승급 → 3종 자재 선택과 외관 미리보기 → 인구/노동력/수요 변화 확인 → 결제·승급.
4. 시설 배치 → 층별 범위·지원 구조·비용 미리보기 → 확정.
5. 경제 화면 → 생산/소비/재고/부족 예상시간, 계층별 잉여 노동력, 운영·무역수지.
6. 탐험 지도 → 부족 재료 필터 → 대상지와 팀 → 파견 → 완료 표시 → 결과·보상 → 도시에서 사용할 곳 안내.
7. 계약 화면 → 다음 도착/출발, 예상 수지, 실패 원인, 수정·정지.

여러 주거 일괄 승급·동일 자재 적용은 편의 후보다. 여러 주거를 한 번에 올릴 때 노동력·이주·재고 전체 합산을 미리 보여준다. 시설 이동과 취소·되돌리기는 비용과 복제 방지 규칙을 먼저 정의한다.

화면에서 즐거운 순간: T1의 작은 촛불, 탐험대 귀환과 자재 펼치기, 재료를 고르며 바뀌는 외관, 주거 승급 비계, 첫 전기의 연쇄 점등, 새로운 층의 골조 형성, 창문·작업·시장 분위기의 계층 차이. 애니메이션이 실제 경제 상태와 모순되지 않아야 한다.

## 17. 세계관·아트·주민 생활

역사적 구룡성채에서 영감을 받되, 다양한 재질·산업·탐험을 허용하는 가상의 성채로 구성하는 기본안을 권한다. 실제 역사에 없던 판타지 설정을 고증 사실로 설명하지 않는다. 핵폭발·특정 연도·대전쟁은 사용자가 확정하지 않았으므로 필수 세계관으로 못 박지 않는다.

오프닝은 버려진 사각형 부지와 첫 주거, 입주자와 초기 작업으로 시작한다. 긴 설명보다 직접 주거 지정·시장 건설·첫 탐험·첫 공급·첫 승급을 경험하게 한다. 플레이어 호칭은 대장/성주/대표 등으로 제안하되 범죄 보스만이 유일한 정체성이 되지 않게 한다.

3D 직교 씬의 픽셀풍 렌더링, 회전·층 단면·줌은 기존 구현을 검토해 재사용한다. 최종 기술 선택은 실행 성능과 미적 검증에 따른다. 기존 방향서의 2D/3D 비용 단정을 그대로 반복하지 않는다. 저해상도 렌더링에서 간판 문자·UI·선택 윤곽이 읽히는지 확인한다.

낮밤은 도시 생활을 보여준다. T1 비취업 주민의 청소·화분·휴식, 작업장 가동, 시장 손님, 촛불·전기·네온을 상태에 연결한다. 직업·계층별 실제 인구 수만큼 모든 NPC를 시뮬레이션할 필요는 없다. 렌더링용 주민 수는 성능 예산 안에서 대표성을 갖게 한다.

주거가 외관의 주요 결정 인자다. 특별 시설 하나를 세웠다고 도시 전체가 테마 스킨으로 바뀌지 않는다. 처음 고른 재료와 뒤늦게 고른 재료의 경계가 ‘선택의 역사’로 남게 한다.

## 18. 산업 분기·음성경제·돌봄의 위치

사용자는 공업·상업·자연친화·음성 경제 등 다양한 성채 가능성을 원한다. 그러나 이제 중심은 Anno식 경제다. 이 요소들을 넣기 위해 기존의 자동 성향·방치 부패 체계로 되돌리지 마라.

산업 특화는 생산품, 요구 노동력, 물·전력, 공간, 수출 계약, 행복 서비스, 위험에서 차이를 만든다. 범죄 사업은 추상화된 업종·계약·사건과 도시 결과로 표현한다. 높은 매출에 의존성·갈등·수급 불안 등의 대가를 제안할 수 있지만 플레이어 권한을 강제로 빼앗는 것이 확정은 아니다.

돌봄은 최하위 비취업 인구와 도시 생활을 풍부하게 하는 방향으로 설계할 수 있다. 고령·질병·실업을 동일한 수치로 뭉개지 말고, 현 단계의 비취업 비율은 게임 계산의 추상 규칙임을 유지한다. 다른 계층에 고정 부양 비율을 다시 추가하지 않는다. 세부 정책은 새 기본 경제를 만든 뒤 사용자가 판단할 수 있는 제안으로 작성하라.

## 20. 시뮬레이션 실행 순서와 검증

렌더러 없이 실행되는 순수 경제 코어를 만들고 시계를 주입한다. 랜덤은 seed를 지정한다. 소비·생산·무역·탐험 보상의 이벤트 로그를 남긴다. 실행 순서는 문서화하고 동일 상태+명령+시드가 동일 결과를 내게 한다.

필수 검사:

- 자금·재고·인구·노동력이 명시한 부채 모델 없이 음수가 되지 않음.
- 한 주민이 생산과 탐험 등에 중복 배정되지 않음.
- 주거 승급·이주에서 인구와 계층별 인원이 보존되거나 명시한 유입·이탈로만 변함.
- T1 정원 4·노동력 3, T2~T5 기준값이 데이터와 일치.
- 같은 승급에서 세 재료 요구 수량이 동일.
- 시장 중복 범위로 수요·세수가 중복되지 않음.
- 시장이 있어도 재고가 없으면 상품 공급이 안 됨.
- 시장 인근 인구 증가가 전체 소비는 늘리되 시장별 물량 상한을 발생시키지 않음.
- 전력 필수 시설이 공급 부족 상태에서 공짜로 생산하지 않음.
- 계약이 실제 결제·물품 이전과 장부에 정확히 한 번 반영.
- 탐험 보상이 완료 전 수령되거나 중복 수령되지 않음.
- 자동 지지대 생성·아래층 철거 후 상층 유지가 일관됨.
- 80% 도달 전/후 경계, 큰 시설 다중칸, 지지대만 있는 칸 처리 확인.
- 오프라인·온라인 경과의 일관성, 재실행·저장복원·버전 변경 확인.
- 해금 그래프에 진행 불가능한 순환 의존이 없음.

### 20.1 봇·시나리오 묶음

| 시나리오 | 확인할 것 |
|---|---|
| 균형형 운영자 | 계층 공존, 생산·수입 혼합, 정상 진행 |
| 승급 과속형 | 하위 노동력 부족을 설명·복구 가능한지 |
| 수출 특화형 | 무역 수입으로 생활품을 구매해 자립 가능한지 |

| 목재/철제/콘크리트 집중형 각 1종 | 같은 경제 조건에서 자재·외관 경로가 모두 유효한지 |

주요 측정치: 첫 입주·첫 파견·첫 수령·첫 승급·첫 전력·층 해금 도달시간, 계층별 인구·여유 노동력, 수요 충족률, 재고 소진 예상, 운영/무역 현금흐름, 외부 공급 의존, 자재별 획득·사용·잉여, 업그레이드 재료 대기시간, 접속당 의미 있는 결정 수, 탐험 슬롯 가동률, 클릭 수, 정체 원인.

목재/철제/콘크리트 시각 차이만으로 합격 처리하지 않는다. 운영 의사결정과 경제 경로가 달라야 한다. 반대로 봇 경제가 안정적이라고 사람에게 재미있다고 주장하지 않는다. 봇은 결함·극단·밸런스 검사이고, 사용자 플레이는 이해·손맛·동기 검증이다.

### 20.2 최상급 경제의 주의점

T3보다 T4/T5 정원이 적다. 1인당 세수만 높이면 한 칸당 세수는 오히려 낮아질 수 있다. 계층별 `세수/칸`, `생활품 비용/칸`, `서비스·유틸리티 비용/칸`, `노동력 가치`, `해금 가치`를 비교하라. 모든 상급 주거가 무조건 이익일 필요는 없지만 아무 경제·기능 가치도 없으면 승급 동기가 사라진다. 자동으로 세수 배수를 정답처럼 고정하지 말고 시뮬레이션해 제안하라.

## 21. 제작 단계와 완료 기준

### 단계 A: 기존 작업 진단과 재기획

실제 저장소·문서·실행 빌드를 확인한다. 기존 경제·성장·수금·주거·저장 코드에서 새 기준과 충돌하는 항목을 표로 만든다. 보존 가능한 렌더러·입력·카메라·에셋을 식별한다. 옛 문서는 역사로 보존하되 현재 기준으로 읽히지 않게 SUPERSEDED 표시한다. 완성 문서를 기다리느라 모든 실험을 중지하지는 말고, 경제 코어와 소규모 화면 프로토타입을 함께 만든다.

### 단계 B: 데이터와 5계층 경제 코어

5계층 정원·노동력·수요·수동 승급·정원 감소·시장·공유 재고·중간 체인·유틸리티·정기 계약을 최소 콘텐츠로 구현한다. T1~T5를 빠른 시뮬레이션으로 통과할 수 있어야 한다. AI가 기획한 수치가 실제 데이터로 옮겨져야 하며 문서에만 남으면 안 된다.

### 단계 C: 20~30분 수직 단면 프로토타입

사용자가 공터에서 주거 지정, 시장 배치, 노동력 확인, 기초 생산/수입, 5~10분 탐험, 보상 수령, 세 자재 중 선택 승급, 외관 변화, 80% 층 해금, 지지대 위 건설까지 경험하게 한다. 첫 접속의 대기시간을 줄이기 위해 튜토리얼 시드 자재와 파견 중 할 일을 제공한다. 일반 탐험 5~10분 규칙을 튜토리얼 편의를 핑계로 전부 없애지 마라.

### 단계 D: 장기 루프

수시간 탐험, 특수자재, 정기 계약 추이, 상급 설비, T3 이후 정원 감소, 계층 공존을 검증한다. 시간 가속 도구와 실제 짧은 대기 테스트를 구분한다. 게임 내 30일과 현실 30일은 같은 표현으로 쓰지 않는다.

### 단계 E: 플레이 피드백 후 개편

사용자 피드백을 결정·수치·콘텐츠·UX·버그로 분류한다. 데이터 변경으로 가능한 것은 먼저 데이터로 바꾸고, 구조 변경이 필요한 것은 비용과 이유를 설명한다. 이전 선택을 지키기 위해 새 피드백을 약하게 해석하지 마라.

## 22. 기존 저장·데이터 마이그레이션

이전 자동 성장형 저장 데이터가 새 모델에 그대로 맞지 않을 수 있다. 원본 백업과 버전 태그를 유지한다. 이전 방·앵커·자재를 새 주거·시설·재고로 합리적으로 매핑 가능한지 평가하고, 불가능하면 개발용 새 도시로 시작하는 방안을 명시한다. 사용자 저장을 조용히 덮어쓰지 않는다.

규칙 버전 변경 시 계약·파견 중 상태·주거 정원·자재 비용이 어떻게 처리되는지 정한다. [제안] 이미 출발한 탐험과 체결된 거래는 해당 시점 파라미터 스냅샷을 저장하고, 이후 새 파견·갱신부터 새 데이터를 적용한다. 조정마다 보상과 비용을 소급 변경해 불공정해지는 상황을 피한다.

## 23. AI가 적극적으로 발명할 영역

다음은 AI의 기획 재량을 넓게 열어둔다: 5계층의 이름과 생활상, 정확한 수요 조합, 업종·상품·시설 목록, 계층별 해금 인구, 소비·생산·세수·유지비·재료 수량, 시장의 단계와 범위, 탐험대 성장, 목적지와 사건, 특별 보상, 정기 계약 상대와 가격, 튜토리얼·세계관 문장, 모바일 조작, 산업 특화와 명물, 높은 단계의 도시 목표.

좋은 제안은 다음 질문에 답한다: 어떤 결정을 새로 만들고, 어떤 화면 변화로 보상하며, 어떤 데이터로 조절하고, 어떤 테스트로 검증하는가? 시스템 개수를 늘리는 것만을 창의성으로 보지 않는다.

아이디어 예시: 탐험에서 발견한 시장 상인과 정기 계약 체결, 특정 재료를 장기간 사용한 동네의 지역 명칭, 원료 부족을 외부 계약으로 버티며 공장 전환, 고층 주거의 물·전력 비용 증가를 상급 시설로 해소, 수출 명품이 된 국수의 지역 간판, 폐열 목욕탕 같은 시설 조합. 이것들은 강제 요구가 아니며 더 좋은 설계를 환영한다.

## 24. 최종 제출물과 다음 행동

AI는 질문 목록만 반환하지 말고 먼저 작업을 진행하라. 최초 결과에는 다음이 포함돼야 한다.

1. 내가 이해한 새 게임과 기존 기획에서 폐기할 항목.
2. Anno 1800 비교 조사와 의도적 차이.
3. 실제 저장소 기준 보존·교체·마이그레이션 계획.
4. 5계층 수요/노동력/해금 표와 시설·상품·생산 체인 데이터 초안.
5. 건축·정원 감소·지원 골조·재료 선택의 예외 규칙.
6. 탐험 월드맵·파견·실시간 귀환·수령·장거리 목표 설계.
7. 정기 계약·도시 금고·전력·물 계산 체계.
8. 데이터 원본과 검토용 표, 버전 관리 방법.
9. 경제 시뮬레이션 결과 및 아직 검증되지 않은 가정.
10. 실행 가능한 짧은 플레이 버전 또는 그 단계의 구체적 완료 증거.

기능·수치·기획 중 무엇이 확정인지 언제나 구분하라. 적극적인 개선을 환영하지만 사용자가 선택한 새 게임을 옛 분재 게임으로 되돌리지 마라. Anno의 경제를 충분히 이해한 뒤 구룡성채의 공간·자재·탐험에 맞게 응용하라.

## 부록 C. 개발 AI에게 보낼 짧은 시작 메시지

첨부한 문서는 기존 구룡성채 기획을 교체하는 최신 사용자 기준이다. 지금까지 만든 분재형 자동 성장 구조에 맞춰 축소 해석하지 말고, Anno 1800의 주민 수요·5계층 노동력·생산·공유 재고·무역 체계를 중심으로 전면 재기획하라. 사용자 확정값은 구현 기준으로 삼고, 제안·실험값은 네가 적극 개선해도 된다. 특히 정원 4-8-12-8-6, 수동 자재 선택 승급, 80% 층 해금과 자동 지지대, 정기 교역, 인구·시설별 물·전력 수요, 외관을 바꾸는 목재/철제/콘크리트, 근거리 5~10분·원거리 수시간 탐험을 빠뜨리지 마라. 기존 구현을 진단하고 출처 기반 조사·데이터 기반 기획·시뮬레이션·실행 가능한 프로토타입을 함께 진행하라. 질문만 늘어놓고 멈추지 말고 가역적 선택은 직접 내리되, 확정 규칙을 바꾸려면 근거와 대안을 명시하라. 핵심 수치와 콘텐츠는 코드와 분리한 데이터 파일로 저장하고, 내 피드백에 따라 언제든 바꿀 수 있게 하라.
