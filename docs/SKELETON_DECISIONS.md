# 구룡성채 — Godot 골격에서 Claude가 임의로 정한 것들 (승인 요청)

> 2026-11-10, 작업 배치 B(Godot 골격). DECISIONS.md에 없어서 골격을 돌리기 위해 Claude가 **임시로** 정한 항목 전부다.
> 각 항목은 코드/JSON에 `PLACEHOLDER` 표시가 있다. 번호로 "그대로 / 바꿔서 X로" 답해주면 반영한다.
> 게임 디자인은 최대한 건드리지 않고, 기술 골격이 돌아가는 데 필요한 최소치만 정했다.

## A. 엔진·프로젝트 설정

1. **Godot 4.7.2 stable** (2026-08-17 릴리스, 조회 시점 최신 stable). Linux x86_64 Standard 빌드를 `tools/godot/godot` 에 둠. 웹 export 템플릿도 같은 버전 설치. — 이유: "최신 stable 4.x" 지시. 로컬에서 다른 4.x를 쓰면 `project.godot`의 `config/features` 가 자동 갱신됨.
2. **뷰포트 540×960** (9:16). stretch `canvas_items` / aspect `expand`. — 이유: 지시대로. 픽셀아트 배율은 에셋 크기가 정해지면 다시 계산 필요(예: 270×480 ×2 같은 정수 배율이 더 선명할 수 있음).
3. **렌더러 gl_compatibility**, 픽셀 스냅 on, 기본 텍스처 필터 Nearest. — 이유: 모바일/웹 호환 + 픽셀아트.
4. **마우스→터치 에뮬레이션 on** (`emulate_touch_from_mouse`). — 이유: 카메라/탭 코드를 터치 하나로 통일하려고. 데스크톱에서 휠 줌은 별도 처리.
5. **디버그 키 바인딩**: `` ` `` 디버그 패널, `F5` 데이터 리로드, `[`/`]` 시각 ±1시간, `N` 하루 넘기기. — 이유: 지시(백틱, F5) + 감상 모드 스크럽용 2개 + 테스트 편의 1개 추가.

## B. 시간

6. **하루 = 600초(10분)** `config.time.seconds_per_game_day`. — 이유: DECISIONS "하루가 몇 분 단위" 범위 안의 중간값. 1~2분/5분/10분/15분 중 선택 바람.
7. **하루 24시간, 시작 06:00.** — 이유: 시계 표기 자연스러움. 오프닝 연출(해 뜨는 황량한 부지)과도 맞음.
8. **오프라인 보상 최대 3일.** 그 이상은 잘라서 요약에 `capped: true`. — 이유: 방치형 밸런스 보호. 그레이프밸리류는 보통 8~24시간 cap. 수치 조정 바람.
9. **큰 시간 점프는 1시간 단위로 쪼개서 시뮬레이션.** — 이유: 오프라인 보상 때도 징수 숙성/부패 타이머가 일관되게 돌도록. 성능상 3일=72틱이면 무시 가능.
10. **감상 모드 = 렌더만 시각 고정(`view_override`), 시뮬레이션은 계속 흐름.** — 이유: DECISIONS "감상 모드에서 시간대 자유 선택"을 "보는 시간대만 바꾼다"로 해석. 시뮬까지 멈춰야 하면 변경.

## C. 격자·아이소

11. **max_floors = 8** (DECISIONS 8~10의 하한). — 이유: 범위의 한쪽 끝. 10으로 바꿔도 코드 변경 없음(JSON만).
12. **아이소 타일 32×16 (2:1), 층 높이 12px.** — 이유: 지시의 플레이스홀더. 에셋 헌팅 결과(배치 A)에 맞춰 바꿔야 함. 전부 `config.iso` 에서 읽음.
13. **좌표 규약**: `screen = ((x−y)·tw/2, (x+y)·th/2 − z·fh)`. 원점은 (0,0,0) 셀 윗꼭지점. — 이유: 가장 흔한 아이소 규약. 에셋의 앵커에 따라 ±오프셋만 바꾸면 됨.
14. **정렬**: `y_sort_enabled` + `z_index = (x+y)·10 + z`. — 이유: "화면 아래 셀과 높은 층이 앞" 보장. 셀 1개가 한 노드이므로 셀 내부 레이어 순서는 노드 자식 순서로 처리.
15. **탭 셀 선택**: 최상층부터 아래로 내려가며 "지어진 셀"이 있으면 그걸 선택, 없으면 지면. — 이유: 가려진 셀 문제의 1차 완화. DECISIONS가 "초기에 풀어야 할 과제"로 둔 UX이므로 **진짜 해법(단면/층 슬라이더 등)은 별도 결정 필요.**
16. **지면 체커보드 폴리곤 + 셀 큐브 3면 폴리곤**으로 임시 렌더. — 이유: 격자가 눈에 보이게. 스프라이트는 `CellRenderer.texture_for_layer()` 한 곳만 채우면 교체됨.

## D. 데이터 파일 내용 (전부 샘플, 로더 테스트용)

17. **업종 4개 샘플**: 옥상 텃밭(농업), 봉제 공방(제조), 마작방(오락), 보이스피싱 콜센터(음성). 수입/인원/위신/해금일 숫자 임의. — 이유: 4분류당 1개씩. 음성 산업은 DECISIONS 톤(직설적 풍자)에 맞춰 이름 그대로 썼음.
18. **정책 기본값**: 산업 허가 = 농업+제조, 입주 = 누구나, 투자 = 증축, 자재 = 목재 우선. — 이유: 오프닝(가난한 초기 성채)에 어울리는 보수적 시작. 옵션별 `effects` 숫자(inflow_mult 1.2/1.0/0.8/1.1, nonworker_ratio 0.2/0.1/0.0/0.2, growth_mult 1.3/0.9/0.9, prestige_per_day ±1~2)는 전부 임의.
19. **정책 효과 합산 규칙**: 키가 `_mult`로 끝나면 곱, 아니면 합, 문자열이면 마지막 값. — 이유: JSON만으로 새 효과를 추가할 수 있게. 다른 규칙이 필요하면 `CityState._policy_effect` 한 곳.
20. **자재 5종**: 목재/철판/네온/녹화(DECISIONS 4개) + **콘크리트** 추가. — 이유: 네온·녹화는 "콘크리트 벽 위에 덧씌우는 레이어"로 표현하려고 베이스 자재가 하나 필요했음. 빼도 됨.
21. **주민 취향 4종**: 소박 / 네온 / 괴짜 기술 / 기묘한 공동체. — 이유: DECISIONS "네온·괴짜 기술·기묘한 공동체 기본" + 중립값 1개. 생체건축·컬트는 후반 해금이라 미포함.
22. **가구 유형 3종**: 가족(2~5명, 노동 60%) / 1인 / 사업체(2~8명). — 이유: "가구/사업체 단위"를 최소로 표현. 사업체가 오면 일터 셀, 아니면 주거 셀.
23. **대표인물 3명 샘플**: 복 할매(첫 입주민, 비노동), 최 기사(전기), 린 언니(마작방). 이름·대사 전부 임시. — 이유: 로더/도착 로직 테스트. 톤 참고용이지 확정 캐릭터 아님.
24. **플레이어 호칭 규칙**: 기본 '대장', 음성 산업 우세→'따거', 제조 우세+인구 60→'회장', 농업 우세→'촌장'. — 이유: DECISIONS "도시 성향 따라 변함"의 데이터 구조 예시.
25. **외형 레이어 슬롯 7개**(base/wall/window/sign/utility/decor/wear), **건물 나이 3단계**(신축≤5일, 낡음≤20일, 노후), **설비 4단계**(무설비/전기/전기+수도/완비). 규칙 17개. — 이유: 5축 합성이 실제로 동작하는지 테스트하기 위한 최소 구조. 레이어 키는 아직 텍스처 없음.
26. **경제 수치**: 초기 금고 200, 위신 10, 세율 20%, 징수 숙성 8시간 / 부패 20시간 / 부패 손실 50%, 유입 1가구/일, 신축 50 / 상층 ×1.5, 위신 10당 거래가 +5%·유입 +10%, 위신 범위 −50~100. — 이유: DECISIONS "플레이스홀더로 프로토타입 먼저". 숫자는 전부 임의.
27. **부패 처리 방식**: spoil 시점에 대기 수입의 50%를 잃고, **남은 절반은 다시 징수 가능 상태로** 돌아감(계속 깎이진 않음). — 이유: 완전 소멸보다 덜 가혹. 그레이프밸리 원본에 더 맞게 바꿀 수 있음.
28. **징수 공식**: 금고 입금 = 대기 수입 × 세율 × 위신 거래가 배율. 나머지는 "주민 몫"으로 사라짐(모델링 안 함). — 이유: 세금 축만 우선. 주민 재산/소비는 미정.
29. **비노동 인구 20%** 는 `housing_care` 정책 옵션의 `nonworker_ratio` 로 구현 (누구나/공동부조=0.2, 노동우선=0.1, 추방=0). — 이유: DECISIONS "유입 인구 중 ~20% 비노동"을 정책 영향 받는 값으로 해석.
30. **시드 20261110**. — 이유: 작업일. 재현성용.

## E. 저장

31. **세이브 = `user://save.json`, `schema_version: 1`**, `_migrate(payload, from_version)` 훅에 v0→v1 예시 1개. — 이유: 지시대로. JSON이라 가구 id(int)가 문자열로 저장되는 문제는 로드 시 복원.
32. **자동저장 시점**: 하루 끝, `APPLICATION_PAUSED`, `WM_GO_BACK_REQUEST`, `WM_CLOSE_REQUEST`(저장 후 종료). — 이유: 지시 + 데스크톱 닫기 추가.
33. **로드 시 오프라인 보상은 자동 적용**, 요약은 `Clock.last_catchup` + 토스트 1줄("자리를 비운 사이 N일이 흘렀다"). — 이유: 요약 UI는 후속 과제라 최소 표시.

## F. UI·폰트·테마

34. **폰트: Galmuri11 (+9, 11-Bold)**, quiple/galmuri, OFL. `assets_raw/galmuri/` 에 이미 받아져 있던 것을 복사. 라이선스 파일 동봉. — 이유: 한글 픽셀 폰트 중 GitHub 공개·OFL. Neo둥근모 등 대안 있음.
35. **테마 색**: 어두운 보라 패널 + 네온 핑크 보더, 기본 폰트 16px. — 이유: "네온 기본" 톤을 흉내낸 임시값. 에셋 팔레트 확정 후 교체.
36. **HUD 레이아웃**: 상단바 52px(일차/시각, 호칭, 금고, 인구, 위신), 하단 탭 64px(정책/제안/성채/기록), 탭 패널 256px, 제안 카드 오버레이 500×360 + 카드 3슬롯 + "나중에" 버튼. — 이유: 지시 항목만 배치. 크기는 임의.
37. **금고 표기 '₩'**. — 이유: 임시. 게임 내 화폐 이름/단위 미정.
38. **단면 보기 스텁 = 셀 정보 텍스트 패널**(좌표, 용도, 자재, 업종, 입주, 나이, 대기 수입). — 이유: 지시대로 스텁.

## G. 낮/밤

39. **색조 그라디언트 8스톱, 하늘 5스톱** (`config.day_night`). 00시 남보라(#2a2f5c) → 06시 주황 → 12시 흰색 → 18시 노랑 → 20시 자주 → 밤. — 이유: 임시. JSON에서 바꾸고 F5로 바로 확인 가능.
40. **CanvasModulate가 World 전체에 적용**, UI(CanvasLayer)는 영향 없음. 하늘은 별도 CanvasLayer(-10)의 ColorRect. — 이유: HUD 가독성 유지.

## H. 입력

41. **탭 판정**: 이동 ≤12px 이고 0.35초 이내. — 이유: 일반적인 모바일 탭 임계값.
42. **줌 범위 0.6~3.0, 기본 1.5.** — 이유: 32×16 타일 기준 임의. 타일 크기 바뀌면 재조정.

## I. 테스트·빌드

43. **스모크 테스트는 `-s` 모드에서 오토로드를 `root.get_node()`로 가져오고, 본문을 첫 `_process`에서 실행.** — 이유: Godot `-s` 스크립트는 오토로드 `_ready` 전에 `_initialize`가 돌고, 오토로드 전역 이름이 컴파일 타임에 안 잡히는 제약 때문.
44. **웹 export 프리셋 = 스레드 미지원(nothreads) 변형**, `data/*.json` 포함. — 이유: GitHub Pages 등 COOP/COEP 헤더 없는 호스팅에서도 뜨게. 성능 필요하면 스레드 변형으로 바꾸고 헤더 설정.
45. **export 템플릿은 web_* 8개만 설치** (전체 1.2GB 중 ~90MB). — 이유: 디스크 절약. 안드로이드/iOS 템플릿은 필요 시 추가.

## J. 코드 구조 (게임 디자인 아님, 참고)

46. `CityState`는 `RefCounted` + 시그널. 노드 트리 없이 headless 밸런스 스크립트에서 `CityState.new()` → `configure()` → `tick()` 으로 사용 가능.
47. `DataLoader`에 `class_name DataLoader` 추가(오토로드 이름은 `Data`). — 이유: 정적 헬퍼(`hex_color`, `gradient_from_array`)를 다른 스크립트에서 쓰기 위해.
48. 오프닝은 **격자 중앙 (6,6,0)에 첫 가옥 1칸 + 로그 1줄**. 튜토리얼 스토리텔링은 미구현. — 이유: 지시 범위 밖. Jin 원안(황량한 부지 → 첫 가옥 → 모여드는 사람들)의 자리만 비워둠.
