### 1. 무엇이 바뀌었나(한눈에)
- **격자 16×16×10**(config `grid`). 층 해금 문턱 = ceil(0.8 × W × H) = 205칸(`Cover.floor_need`, `floors.eligible_cells` 0 = W×H). 12를 가정하는 코드 없음.
- **시설 모양**: `footprint:[w,h]`, `floors:1|2`, `build {type, pos, rot}`(rot 1 = w·h 바뀜). 셀·건물에 `origin,w,h,d,rot,size(=max(w,h))`. 골조·철거·층 해금이 여러 칸·두 층을 안다(2개 층 시설은 두 층 모두 열려야 하고 두 층에 칸을 쓴다). can 결과 `cells`·`supports`(골조 칸 배열)·`support_count`·`code`(+ `shape`·`sky`·`floor`).
- **사각 범위**: `range:{r,up,down}` — 발자국 사각형에서 체비쇼프 r, 시설 맨 아래층 −down … 맨 위층 +up(`Cover.reach`·`reach_b`). 다이아몬드·층 가중치(`distance.*`)는 지웠다. `range_preview {type,pos,rot}` → `{cells, by_floor, houses, text}`.
- **하늘·층 조건**: `needs_sky`(옥상 텃밭·하늘 공원) — 위가 뚫린 자리만 짓고, 나중에 위에 무엇이 서면 **멈춘다**(cause `sky`, 허물면 다시 돈다 — 부수지 않는다. 결정 45). 위에 지을 때 can 결과에 `warn` 문장. `min_floor`(z 기준, 2 = 3층).
- **게임 시계만**: 실제 시계·미접속 정산 제거(`Sim.catch_up`·`fast_forward` 삭제, `time.offline_speed` 0, `offline_summary`는 늘 null). 탐험·연구·계약·공사 모두 `econ_days`. Game: `speed`(1·2·4, 디버그 아무 값)·`paused`는 세터 — 바뀌면 `speed_changed{speed,paused}`. 명령은 멈춤 중에도 된다. 저장 `user://save_v4.json`(CityState v4), 디바운스 자동 저장 유지. hud의 `speed`·`paused`는 Game.query가 채운다.
- **공사·입주**: 시설은 `site`(발자국 전체)로 시작해 `build_days`(데이터, 없으면 config `build.days_by_cells`: 1칸 0.1 · 2칸 0.15 · 4칸 0.3 · 8칸 0.5 · 9칸 이상 2.5일)에 완공(`construction_done`). 명소는 2~3일. 주거는 바로 서고 주민은 행복이 높을수록 빨리 들어온다(기존 규칙) — `arriving`(입주 진행 0..1), info `arriving_text`.
- **탐험(게임 시계)**: 자동 파견 근거리 0.3일·중거리 1일·원거리 3일(옛 발전소 4일). 목적지마다 **던전 재고**(`stock{상품:최대}`, 하루 최대치 × `regen` 회복) — 자동 파견도 직접 줍기도 여기서 뺀다. 직접 줍기 약속: `run_begin {dest}` → `{ok, stock, danger, seed, carry, team}`(팀 하나가 `run`), `run_result {dest, loot, outcome, finds}` — 짐은 던전 재고와 배낭 칸(`run.carry`, 기본 40)으로 검사, 넘치면 전체 거절(code `stock`·`carry`), `down`이면 절반(나머지는 `lost`), `boss`면 `run.boss` 덤, finds는 `"partner:id"`·`"blueprint:id"`·`"dest:id"` 중 그 던전이 줄 수 있는 것만.

### 2. 콘텐츠 규칙(데이터 요약 — 전체 표는 `docs/data_tables/`)
- **1층 필수 셋**: 굴러온 돌의 기본 수요 = 식수(1) · 끼니 통조림(2, 시장 범위) · **놀 거리**(1, 패가망신 클럽). 놀 거리는 모든 계층의 기본 수요(마작·찻집·노래방·카지노).
- **먹을 것 사다리**: 통조림(찌그러진 캔 은행·마감 세일 순례단, 원료 없음) → 완탕면(수타 제면소 → 완탕 한 그릇) → 쥐고기 버거(쥐덫 조합 → 출처 묻지 마 버거) → 스시(생선 수입 → 어제 잡은 스시) → 신선 채소(하늘 텃밭: 위가 뚫린 3층 이상).
- **성채식 조달**: 원료를 수입해 가공하는 공장이 없다. 사슬은 길어야 2단(둘 다 성채 안): 기름 수거단 → 초·비누, 넝마 수거단 → 봉제방·맞춤 양복점, 제면소 → 완탕, 쥐덫 → 버거. 원료 없는 것: 캔 은행·순례단·부스러기 양조장(Jin의 문장 그대로)·수거함 정리단·고물 분해소. 전자 폐품·설비 부품 = 탐험(고물 분해소가 전자 폐품을 조금). **수입은 진짜 사치품뿐**(생선·양주, + 비싼 건재).
- **승급 관문**: 굴러온 돌 → 헌 옷·초 / 월세 전사 → 비누·밀주·**전기** / 박힌 돌 → 라디오·공부방 / 깡통 귀족 → 양주·짝퉁 명품 + 설비 부품.
- **교역 = 중반 시스템**: 계약 기본 자리 0 — 뒷문 무역관(월세 전사 40명)을 지어야 계약. 수입은 생선·양주·건재(비싸게), 수출은 남는 것.
- **사치 시설**(때밀이 성전·발치 전문·약 비슷한 것 약국·가위손 이모·하늘 공원): 비싸고, 해금 조건에 계층 인구 + **"도시 행복도 n 이상을 m일 유지"**(새 지표 `happy_held.<n>`, progression이 `flags.happy_since`에 연속 시작 시각을 둔다).
- **모양**: 기본 1×2, 강한 것 2×2(시장 2~4등급·정수장·발전소·소방서·조립소·목욕탕·하늘 공원), 작은 설비 1×1(하늘 수도국·수도관·문어발·사당), 명소 = 네온 용탑 2×2×2층 · 무허가 구청 3×3. 주거는 1×1. 모든 시설에 `look`(계약 목록), `sign`(한글 4자 이내 — 검증), 한자 금지(검증).
- **이름**(§8): 계층 굴러온 돌·월세 전사·박힌 돌·깡통 귀족·옥상 황제. 등급·호칭 공터/무단 점유 대표 → 판자촌/자칭 반장 → 골목/비공식 통장 → 성채/무허가 구청장 → 구룡/세금 안 내는 시장님 → 구룡성채/지도에 없는 곳의 따거. 던전: 고물 야적장·쓰레기 매립지·철거 현장(근) · 폐공장·부두 뒷골목(중) · 폐기물 처리장·버려진 신도시·옛 발전소(원). 정책·연구도 같은 결(반 공기 운동, 봉투 문화, 약도 그리기…).
- **목표 24단계**: 칠하기 → 필수 셋 → 굴러온 돌 20 → 탐험 → 수령 → 첫 승급(자재 고르기) → 완탕(첫 사슬) → **2층(불)** → 소방대 → 월세 전사 40 → 첫 전기 → 첫 박힌 돌 → 중거리 → **3층(병)** → 수거·의원 → 무역관 계약 → 박힌 돌 80 → 사치 시설 → 첫 깡통 귀족 → 원거리 → 네온 용탑(첫 명소) → 첫 옥상 황제 → 무허가 구청 → 마지막(옥상 황제 N + 구청).

### 3. 불·병(`sim/systems/hazards.gd`, config `hazards.*`)
- 켜짐: 불 = 2층이 열리면, 병 = 3층이 열리면 `hazard_on{kind, grace_days}` + 기록 한 줄. 유예(2일) 동안은 위험이 쌓이지 않는다. 디버그 `set_hazard`로 강제(유예 0).
- 범위: 방재 시설의 서비스 태그 `fire`·`trash`·`clinic`(config `hazards.tags`)은 주거 수요가 아니라 Cover가 **주거·시설 모두**에 대해 `hz[tag][bid] = [시설…]`로 계산한다. "덮임" = 그중 가동 중인 시설이 하나라도 있음.
- **불**: 쓰이는 건물마다 위험 0..1이 하루 `risk_per_day`(범위 안이면 × `covered_mult` 0.1)씩 쌓인다. 한 경제시간마다 결정론 RNG로 위험 합 × `ignite_per_day` × dt 확률(상한 0.5)로 위험 비례 한 곳에 불(불 사이 `min_gap_days`, 동시에 타는 곳 `max_burning` + 쓰이는 건물/`burning_per` 이하). 범위 안 불은 `out_days`(약 1시간)에 꺼지고 주민 1명만 흩어진다. 범위 밖은 `burn_days`(0.3일) 타며 매시간 범위 밖 이웃(가로·세로·위)으로 `spread_per_day` 확률로 번지고, 끝나면 `burnt`: 주민은 **흩어져 대기 주민**(3일 안에 빈집을 찾거나 떠남 — 인구가 조용히 사라지지 않는다), 시설은 멈춤(cause `burnt`). `repair {bid}` = 돈(주거 계층별 / 시설 건설비 × 0.4) + 고물(칸당 3) + 0.25일 → `repaired`.
- **병**: 주거마다 쓰레기 0..1이 수거 범위 밖에서 하루 `trash_per_day` × 주민/정원씩 쌓이고(셀 `trash`는 0.1 단위), 안이면 `clear_per_day`씩 준다. 매시간 `outbreak_at`(0.7)을 넘은 집들에서 결정론 RNG로 발병 — 그 집과 이웃(가로·세로 1칸, 위아래 1층)의 쓰레기 많은 집(최대 6채, 동시에 앓는 집 상한 8%·최소 6채). 앓는 집: **일손 절반**(workforce), 행복 −15(도시 평균에도), 세수 ×0.8, 새로 안 들어옴, 1일 뒤부터 하루 2명씩 떠남. 2.5일 뒤 낫고, 무면허 의원 범위면 0.6일(앓는 중 범위에 들어도 줄어든다).
- 세 자재 계열의 차이는 없다(확정). 표시: 셀 `burn`/`sick`/`trash`, 건물 `burn`/`sick`/`sick_until`/`repair`, 질의 `hazards`·`coverage`, hud `hazards`·`signals`, 알림 `fire`(jump `focus` "x,y,z")·`burnt`(inspect)·`fire_cover`(jump `lens` fire)·`sick`(focus)·`trash_cover`(lens trash|clinic). 이벤트 `fire_started`·`fire_spread`·`fire_out{burnt}`·`repaired`·`outbreak{bids,pos}`·`outbreak_end`·`hazard_on`.
- 손실 장부(stats): `house_days`, `hz_fire_house_days`(탄·타는 주거), `hz_sick_house_days`(앓는 주거 × 0.5) — 봇 보고서의 "불·병 손실 %".

### 4. 현황판·신호등(`sim/Board.gd`)
- `metrics` 질의 = 현황판: `rows`(물·전기 / 먹을 것 단계별 / 그 밖 상품 / 서비스·시장 범위 / 불·병) 각 `{id, group, name, supply, demand, unit, ratio, state, days_left, hint, jump, stock?}`, `labor`, `tiers`(+`arriving`), `finance`(어제 장부: income·cost·net·lines), `hazards`. 상품 수요 = 계층 인구 × 1인 소비 + 가동 시설 원료, 공급 = 최근 1일 생산 + 수입. 옛 지표 사전은 `metrics_raw`.
- `hud.signals` = 물·전기·먹을 것·놀 것·불·병·일손 7개 `{id, name, state ok|warn|bad|off, text, jump}`(스텝마다 한 번 계산해 캐시).
- `coverage {kind}` = `market`·`fun`·`fire`·`trash`·`clinic`·`service:<시설 id 또는 태그>` → `{covered, uncovered, pct, text}`(쓰이는 칸 기준).

### 5. 봇·러너
- `sim/Bot.gd` 새로 씀: 발자국·회전을 모두 시험, 범위 시설은 "아직 안 덮인 대상을 가장 많이 덮는 자리", 층마다 2×2 구멍(x, y mod 5 ∈ {3,4})을 시설 자리로 남기며 가운데부터 칠한다, 자리가 없으면 낮은 계층 주거를 허문다. 방재(불·쓰레기·의원) 범위를 덮고, 탄 건물을 수리하고, 2단 사슬은 원료가 모자라면 원료 시설을 먼저, 돈이 모자라 미룬 꼭 필요한 시설의 돈을 다음 손길까지 남기고(`flags.bot.want`), 일손이 모자라 못 지은 계층을 기억해 승급으로 채운다(`labor_want` — 교착 방지).
- 봇 10종(`data/sim/bots.json`): 균형형·승급 과속형·수출 특화형·자급형(교역 없음)·목재/철제/콘크리트 집중형·공간 부족형·**방재 무시형**·**느긋한 사람형**(4시간마다, 적게).
- `tools/sim_run.gd` = 게임 시계로 계속 플레이(봇은 `act_every_h`마다) → `simulation/reports/<봇>.md/.json`. `simulation/run_all.sh [days] [seed]`가 둘씩 나란히 돌리고 `make_summary.py`가 `SUMMARY.md`를 쓴다. `tools/sim_debug_run.gd`(튜닝용 들여다보기), `tools/sim_perf.gd`(16×16×10 도시, 불·병 켬).

### 6. 감독 확인 사항(2026-11-13, UI·VIEW 통합 뒤) — 반영
1. `Game.set_speed(v)`·`Game.set_paused(on)` + `Game.speed`/`Game.paused` 직접 쓰기도 세터라 둘 다 `speed_changed{speed,paused}`.
2. can build `cells` = 발자국 전체 부피(2개 층이면 위층 칸 포함).
3. info 시설·공사장에 `build_progress`(0..1, 완공 시설은 1.0)와 `build_left_text`. 주거 `arriving`은 숫자, 화면은 `arriving_text`.
4. metrics 행에 `stock`(상품 행은 재고, 물·전기·서비스·불·병은 null).
5. jump는 알림·신호등·현황판 모두 `{screen, arg}` 한 가지: `build`(arg 시설 id·분류·"water"/"power"), `economy`, `metrics`(arg 행), `lens`(arg fire·trash·clinic·market·fun·service:<id>), `focus`(arg "x,y,z"), `keep`, `expedition`, `trade`, `upgrade`, `inspect`(arg bid).
6. 짓기 분류 id(고정): `house` 주거 · `market` 시장 · `water` 물 · `power` 전기 · `food` 먹을 것 · `goods` 생활품 · `electronics` 전자 · `service` 놀 것·서비스 · `safety` 방재(양동이 소방대·무허가 소방서·넝마주이 조합·무면허 의원) · `vice` 음성 · `infra` 기반 · `landmark` 명소.
7. `hazard_on{kind, grace_days}`은 도시마다 한 번(`flags.hz.<kind>.announced` 저장) — 불러오기·디버그로 껐다 켜도 다시 안 낸다.
8. 디버그 `start_fire`·`start_outbreak`의 `pos`는 생략 가능 — 주민 있는 주거 하나를 결정론 RNG로 고른다.
9. `run_begin` → `{ok, reason, stock, danger, seed, carry, carry_cap, team}`, 쉬는 팀이 없으면 `{ok:false, code:"busy"}`, 팀 `state "run"`·`state_name "직접 줍는 중"`, `run_result`가 팀을 놓아준다.
10. 시설·공사장·셀에 `front`(0..3, 입구 방향 = 지금은 rot과 같음 0|1 — 뷰가 더 세밀히 원하면 데이터로 늘린다). 시설 `staff`는 0..1 비율(계층별 배정/필요의 최솟값).
11. 주거 셀에 `trash`(0..1, 0.1 단위), 모든 셀에 `burn`·`sick`(건물과 같은 값).
12. `hud.tiers:[{tier, name, pop}]`(일손과 무관).
13. 모든 `sign`·`name`·`desc`에 한자 없음 — `Validate`가 검사(한자가 있으면 데이터 오류).

### 7. 내가 정한 것(v4) — 번호(v0.3의 44 다음부터), 이유
45. **하늘 시설은 위가 막히면 멈춘다(부수지 않는다)** — cause `sky`, 위를 허물면 다시 돈다. 짓는 순간 can 결과 `warn`으로 알린다. "죽는다"는 되돌릴 수 없어 벌이 너무 크고, 멈춤이면 "높이 올릴까 텃밭을 지킬까"가 그대로 선택으로 남는다.
46. **2개 층 시설의 범위는 위층도 자기 층으로 친다**(−down … 맨 위층 + up) — 계약 문장 그대로.
47. **방재 범위는 주거 수요가 아니다** — `fire/trash/clinic` 태그는 Cover가 주거·시설 모두에 대해 따로 계산하고 주거의 덮임 등급(cls)에서는 뺐다. 그래야 needs 묶음 캐시가 방재 시설 때문에 쪼개지지 않고(성능), 불은 시설에도 난다.
48. **탄 집의 주민은 사라지지 않고 대기 주민이 된다**(3일 안에 빈집을 찾거나 떠남). "인구는 조용히 사라지지 않는다"(v0.3 원칙)를 지키려고. 방재 무시형의 손실은 그래서 "떠남"보다 "흩어짐·주거-일 손실"로 보인다.
49. **소방 범위 안의 불은 탄 집 없이 주민 1명만 흩어진다**, 범위 안 건물도 위험이 0.1배로 쌓여 가끔 불이 난다 — 범위가 "일하는 것"을 화면에서 보여 주려고(양동이 줄).
50. **불·병 상한**: 동시에 타는 곳 2 + 쓰이는 건물/150, 불 사이 0.15일, 앓는 집 8%(최소 6채), 발병 이웃 6채. 도시를 통째로 태우지 않게(과제 조건).
51. **손실 지표 = 탄·타는 주거-일 + 앓는 주거-일 × 0.5**(앓는 집은 일손 절반이라).
52. **전기를 월세 전사 승급 조건으로**, 털털이 발전기·문어발은 "2층 + 월세 전사 40"에 연다 — 첫 박힌 돌이 2층(첫 불) 뒤에 오게(목표 순서 2층 → 소방대 → 전기 → 박힌 돌).
53. **"등불 대신 전기"(남을 때만 쓰는 유틸리티)는 도시 전체 공급 ≥ 수요일 때만** — 주민 몫 비율로 보면 월세 전사 수천 명이 전기를 쥐고 시장·전파사가 굶어 사슬 전체가 무너졌다(튜닝 T5·T8).
54. **교역은 뒷문 무역관이 있어야**(기본 계약 자리 0) — 과제의 "교역 = 중반 시스템".
55. **던전 재고는 자동 파견과 직접 줍기가 같이 쓴다**, 하루 최대치의 80% 회복. 직접 줍기 짐이 재고·배낭을 넘으면 결과 전체를 거절(부분 반영 없음 — 미니게임 쪽 버그를 숨기지 않게).
56. **run_result의 finds는 "type:id" 문자열**, 그 던전이 줄 수 있는 것만 반영(나머지는 조용히 무시). 처음 직접 다녀오면 그 던전의 reveals도 공개.
57. **면세 백화점·카지노는 2×2 한 층**(처음엔 2개 층). 2개 층 시설을 범위에 맞춰 놓을 자리가 꽉 찬 도시에서 사실상 없어 깡통 귀족이 막혔다(튜닝 T9·T10). 2개 층은 명소(네온 용탑)만.
58. **마지막 목표 = 옥상 황제 60명 + 무허가 구청**(v0.3은 거물 150). 옥상 황제 집 10채. 16×16에서 120명을 40일 안에 채우는 봇이 없었다(튜닝 T11~T12).
59. **승급 비계 날짜**: 0.05/0.25/0.5/1.0일 — "건설에 시간이 든다"를 승급에도. 돈: 40/300/2,000/4,000(+부품 2). 자재: 4/30/40/80.
60. **공사 기본 날짜를 칸 수로**(config `build.days_by_cells`) — 시설마다 숫자를 쓰지 않아도 모양이 곧 공사 시간.
61. **Game 한 프레임 dt 상한 0.25초**(창을 끌다 멈춘 프레임이 몇 시간치를 몰아 돌리지 않게) — 정산이 아니라 끊김 방지.
62. **해금 판정 2경제시간마다 + 명령 직후**(Metrics 계산이 큰 도시에서 무겁다). 목표와 같은 주기.
63. **hazard_on은 도시마다 한 번**(감독 확인 7).
64. **사치 시설 조건 "행복도 n을 m일 유지"** = 새 지표 `happy_held.<n>`(도시 평균 행복이 n 아래로 떨어지면 다시 0부터).
65. **봇 전용**: 층마다 2×2 구멍(x, y mod 5 ∈ {3, 4}) 자리 비우기, 꼭 필요한 시설은 낮은 계층(≤ 박힌 돌) 주거를 허물어 자리, 명소 몫 자재·돈 남기기, 수입 원료 시설(스시)은 먼저 짓고 계약. 사람에게 강요하는 규칙이 아니다.
66. **현황판 수요 = 계층 인구 × 1인 소비 + 가동 시설 원료**, 공급 = 최근 1일 생산 + 수입 — 재고 수치보다 "며칠 버티나"를 먼저 보이게.

기준: `docs/GDD.md` v0.3 + 디렉터 수정 · 브랜치 `simb`. 수치 변경 이력은 `docs/BALANCE_CHANGELOG.md`, 검토용 표는 `docs/data_tables/`(자동 생성, `python3 godot/tools/data_tables.py`),

UI 계약에 덧붙인 것(키 이름 변경 없음)은 `docs/ARCHITECTURE.md` 끝 "파트 B 추가" 절.

## 1. 구조 한눈에

- **순수 규칙 층**: `godot/sim/**`는 노드·오토로드·`Time.*`를 쓰지 않는다. 경제 시간은 `Sim.tick(state, dt_경제일)`로만, 실제 시간은 `sim.now_unix`(Game이 매 프레임 = 시스템 시각 + `state.clock_offset`)로만 들어온다.
- **고정 스텝**: `config time.step_days` = 1/48 경제일(실제 12.5초). 미접속 빨리감기는 그 12배(1/4경제일) 큰 스텝 — 경제 시계 격자는 그대로(`econ_days`는 늘 1/48의 배수).
- **RNG**: xorshift32 하나, 상태는 `state.rng_state`(외형 씨앗, 탐험 보상 굴림, 단속 대상).
- **시스템 = 파일 하나** (`sim/systems/<id>.gd`): `config.json systems` 순서대로 매 스텝. 하나를 빼도 돈다(시험). 시스템끼리 부르지 않고 `CityState`와 Sim의 공용 도우미만 쓴다.
- **공용 도우미(규칙 아님)**: `Cover.gd`(배치 파생 캐시: 주거·시설 목록, 덮임 등급, 우선순위 묶음, 층별 목록 — `layout_rev`가 바뀔 때만), `Queries.gd`, `Metrics.gd`, `Validate.gd`(파트 B 데이터 검사 `check_b` 포함), `Debug.gd`, `Expr.gd`.
- **수정치 접근자 하나**: `sim.mod(state, "키")` = 1 + Σ(켜진 정책 + 끝난 연구의 effects[키]), `sim.mod_sum`은 합만. 연구·정책이 바뀌면 `state.flags.mods_rev` +1 → 캐시 갱신.

### 한 스텝의 실행 순서
`progression → goals → space → contracts → expeditions → research → policies → workforce → utilities → production → needs → upgrades → vice → finance → alerts`
→ (Sim) 상품 흐름 접기 → 시계 전진 → 정시 `hour` → 자정이면 `on_day_end` → `day_ended` → `on_day_start` → `day_started` → `state.settle()`(빨리감기 중에는 끝에서 한 번).
순환이 있는 곳은 직전 스텝 값(전기 비율, 수요의 물·전기 비율). 알림·목표 검사는 2·4스텝 주기의 경계(`sim.every`) — 스텝 크기·저장과 무관하게 econ_days로만 정해진다.

## 3. 파트 B 규칙 요약

- **탐험**: `expedition_send {team, dest, provision, pick?}` — 팀이 쉬는 중·목적지를 앎·출발비·보급(끼니 10, 채소·국수·어묵 중 많은 것부터)을 확인하고, **출발 때** 보장 주력(min~max) + 덤(확률) + 발견을 결정론 RNG로 굴려 팀에 저장. `completes_unix = now + seconds × exp.time`. `now ≥ completes`면 done(`expedition_done` 한 번). 수령은 done인 팀만 정확히 한 번(재고 한도를 넘겨도 넣는다 — "결과는 사라지지 않는다"). 근거리는 처음부터, 중거리는 첫 근거리 수령·목표 `g_claim`, 원거리는 중거리 수령·연구 `지도 제작`으로. 거점을 허물면 쉬는 팀부터 없애고, 나가 있는 팀은 은퇴 표시 → 수령 뒤 해산.
- **목표**: goals.json 순서로 하나씩 보이지만 먼저 이룬 것도 그때 끝난다. 마지막 `g_final`(거물 40 + 성채 회관) 뒤 샌드박스.
- **알림**: 물·전기 부족, 일손 부족(계층별), 재고 하루 안에 바닥/없음, 계약 건너뜀, 탐험 귀환, 승급 가능, 층 해금 12칸 이내, 대기 주민 곧 떠남, 주민 잃는 주거, 파산 정지, 단속 위험 50, 단속 폐쇄. 조건이 꺼져도 1경제시간 남긴다. 4개까지(bad → warn → good, 같은 tone은 고정 순서).
- **미접속**(`Sim.catch_up`): 실제 경과(마지막 정산 → 지금, 음수면 0 + 한 줄, 8시간 상한 + 한 줄) × 0.25 / 600 → 경제일, `fast_forward`(offline 표시) — 유예 시계·대기 시계 정지(아무도 안 떠남), 재고 0이면 그 소비·생산만 멈춤, 계약·연구는 경제 시계, 탐험은 실제 시계로 완료. 요약: 금고 변화, 많이 만든·쓴 것, 처음 모자란 때(떠난 지 몇 시간째), 계약 이행/건너뜀과 이유, 연구 완료, 단속, 돌아온 탐험대. Game은 불러올 때 + 프레임 사이 공백이 60초를 넘을 때(앱 복귀) 부른다. 디버그 `skip_real`은 공백으로 치지 않는다.
- **연구·정책**: §2 표. 연구는 공부방이 하나도 가동하지 않으면 멈춘다.
- **음성·단속**: 가동 중인 음성 시설 vice.heat × 가동률 × heat.gain/경제일, −6/경제일. 80에서 기여만큼의 확률로 하나 골라 2경제일 폐쇄(`raided`, `raid_until`, cause raid, 인력 0), 벌금 max(₩100, 수입 2일치)(금고를 넘지 않음), 위험 −40. 닫힌 동안에도 멈추기·허물기는 된다.
- **승급 표시**: `upgradable` = 지금 바로 승급 가능(조건 + 돈 + 한 계열 이상 자재 + 추가 상품) — 뷰의 ▲가 넘치지 않게(디렉터 요청). 비용을 뺀 조건 충족은 `ready`(봇·UI용). `upgrade` 명령은 `ready`와 실제 비용으로 판정.

## 5. 성능

측정: `godot --headless --path godot -s res://tools/sim_perf.gd -- [houses=1000] [steps=96] [topup=1] [offline=1]` — 주거 1,000채(층마다 2×2 시설 자리 여섯 곳, 계층 층마다 다름, 정수장 30·열병합 12), topup=1은 생산 시설 없는 상품을 매 스텝 채움(정상 운영), topup=0은 끼니가 바닥나는 위기 도시.

| | 파트 A | 지금 |
|---|---|---|
| 1,000채 스텝 평균(정상) | **약 120ms**(파트 A 측정) · 이 탐침 267ms(needs 250) | **약 7.7~8.3ms**(중앙값 6.8~7.5, 하루 경계의 settle 포함) |
| 1,000채 스텝(위기: 매 스텝 고르기가 뒤집힘) | — | 약 15ms |
| 하루 경계 settle | 32~37ms | 30ms(한 번의 JSON 왕복) |
| 미접속 8시간(12경제일) 정산 | 약 70초(576스텝) | **약 0.9초**(48 큰 스텝 + 끝 settle 한 번) |
| 시험 묶음 | 13.8초 | 약 17초(시험 수 2배) |

어떻게(결과는 같다 — 균형형 봇 30경제일 결과가 파트 A와 숫자 하나 다르지 않았다, 탐침 지문 동일):
1. **덮임 등급 → 접근 등급**: Cover가 주거마다 (시장 목록, 서비스 목록, 소음)을 등급으로 묶고, needs가 범위 시설의 가동 상태가 바뀔 때만 등급별 "시장 등급·서비스별 원인" 표를 만들어 같은 것끼리 다시 묶는다(1,000채 → 642 → 158).
2. **묶음(Ent)**: (계층, 접근 등급, 현재 선택 서명 psig, prefer 판정 비트)가 같은 주거는 1단계 결과가 같다 → 한 번만 계산하고 주거마다 주민 수만 더한다. 묶음은 기댄 환경 비트(상품 재고 있음·공급률 충분, 물·전기 0.5/충분)가 그대로면 다음 스텝에도 쓴다. 재고 양으로 정렬해 고른 묶음은 그 스텝만.
3. **2단계 결과(P2)** 도 묶음마다(공급률·물·전기 값이 그대로면 재사용). **가라앉은 주거**(같은 묶음·같은 P2·같은 주민 수·부족 일수 변화 없음·입주/퇴거 없음)는 2단계를 통째로 건너뛴다.
4. 소비는 소비 묶음(dem)별 주민 합 × 1인 소비, 상품 순서는 데이터 순서로 고정 — 캐시 이력과 무관하게 결정론. 도시 행복도 묶음 순서로 더한다.
5. Cover의 우선순위 묶음(시설 정보 배열)으로 workforce·utilities가 사전 조회 없이 돌고, Metrics·finance·upgrades·space가 주거·시설 목록만 돈다. `Sim.cfg` 경로 캐시, `bdef/good/tier` 빠른 길.
6. settle은 정수 아닌 float만 모아 JSON 왕복 한 번. 빨리감기 중에는 끝에서 한 번.

휴대폰(5~10배 느림) 예상: 정상 스텝 40~80ms(×16이면 실제 0.78초에 한 번 → 프레임 하나), 미접속 8시간 5~9초 — 로딩 화면이 필요할 수 있다(§9 열린 질문).

## 7. 내가 정한 것(사양 밖) — 번호, 이유

파트 A의 1~19는 그대로 유효(아래는 파트 B, 20부터).

20. **부족 일수(유예 시계)는 유예(3경제일)에서 멈춘다.** 원래는 끝없이 쌓였다. 쌓인 값은 "회복 뒤 다시 끊기면 얼마나 빨리 떠나나"에만 영향을 주는데, 상한이 있어야 오래 굶은 집도 회복 뒤 다시 유예를 온전히 받고(더 너그러움), 묶음 캐시가 "변화 없음"을 알아볼 수 있다.
21. **`upgradable`에 비용을 넣고 `ready`를 따로 둠**(디렉터 요청을 따르되 봇·UI가 "조건은 됐는데 돈/자재가 없음"을 알 수 있게). `upgrade` 명령은 ready + 실제 비용으로 판정.
22. **탐험 보상은 출발 때 굴리고, 발견(거래처·도면·새 목적지)은 수령할 때 적용.** 보상이 미리 정해져 있어야 저장·불러오기·시계 조작으로 다시 굴릴 수 없고, 발견은 플레이어가 짐을 풀 때 보여 주는 게 자연스럽다.
23. **수령은 재고 한도를 넘겨도 넣는다.** "결과는 사라지지 않는다"(확정)를 지키려고. 넘친 만큼 생산·수입이 멈출 뿐.
24. **세 근거리 목적지의 실제 1분당 자재를 같게(2.0)**: 가구 골목 5분·10, 고철 7분·14, 철거 공사장 10분·20(GDD는 10/10/12). 어느 계열도 정답이 아니게(브리프 요구), 대신 짧은 곳은 손이 더 간다.
25. **출발비**: 근거리 0, 중거리 ₩30, 원거리 ₩80. 작은 돈 싱크 + 원거리를 공짜 무한 수확으로 만들지 않으려고.
26. **거점을 허물면 쉬는 팀부터 없애고, 나가 있는 팀은 돌아와 짐을 푼 뒤 해산.** 팀 수 = 거점 수를 지키면서 보상을 잃지 않게.
27. **목표 보상에 돈·설비 부품·목적지 공개**를 넣고, 등급·호칭은 해금 단계(unlocks.json)에 그대로 둠. 목표는 "다음에 할 일" 안내, 등급은 성장 결과.
28. **알림은 상태(flags.alerts)에 기억해 1경제시간 유지**, 최대 4개. 탐험 귀환처럼 실제 시계에 따르는 것만 질의 때 바로.
29. **미접속 큰 스텝 1/4경제일**(접속 중 1/48). 계약 주기(12시간 이상)·공사(0.04일)·입주 속도에서 결과가 거의 같고(시험: 37분씩 나눠도 ±2%), 1,000채 8시간을 1초 안에.
30. **앱이 60초 넘게 멈췄다 돌아와도 미접속 규칙**으로 정산(접속 중 속도로 몇 시간을 몰아 돌리지 않게). `last_saved_unix`를 "마지막 정산 시각"으로도 씀.
31. **연구는 공부방이 하나도 가동하지 않으면 멈추고, 취소하면 절반 환불.** "공부방 필요"를 진행 조건으로 읽었다.
32. **정책 유지비를 못 내면 그 정책이 저절로 꺼진다**(금고 음수 금지 규칙과 맞춤).
33. **단속 대상은 위험 기여만큼의 확률로**(결정론 RNG), 벌금은 금고를 넘지 않는다. "권한을 빼앗지 않는다": 폐쇄 중에도 멈추기·허물기 가능, 위험은 공개(hud.heat, vice 질의, 알림 50).
34. **무면허 치과·짝퉁 공방도 위험을 조금 올린다**(1·4). GDD §11의 음성 여섯 곳을 그대로.
35. **봇 전용: 꼭 필요한 시설 자리가 없으면 낮은 계층 주거(최대 세입자)를 허물어 2×2 자리를 낸다.** 알려진 약점(층이 차면 2×2를 못 놓음)을 플레이어가 하는 방식으로 — 주거 철거는 무료, `can("build")`가 "이 층에는 빈 2×2 자리가 없다 — 주거 한 칸을 허물면…"이라고 말한다.
36. **목표 `g_trade`의 계약 3건, `g_mid`(중거리에서 거래처)** 등 목표 문구·순서는 내가 썼다(goals.json).
37. 초반 현금(시작 ₩1,200, 초반 목표 보상↑), 후반 싱크(세율·승급 돈·연구·회관) — BALANCE_CHANGELOG에 이유와 함께.

## 10. 파트 C(다지기) — 캐시 검증과 글 고침

### 캐시 끄기 스위치 `sim.no_cache`
시험 전용(Game은 쓰지 않는다). true면 스텝을 넘는 기억을 모두 끈다:
- `Sim.cover`: 스텝 시작과 명령 앞뒤마다 다시 만든다(`layout_changed`를 빠뜨린 경로가 있으면 캐시 쪽이 어긋난다).
- `Sim.mod_sum`: 부를 때마다 연구·정책 효과를 다시 더한다.
- needs `_forget()`: 묶음(Ent)·2단계(P2)·주거별 빠른 길(`_hent/_hp2/_hres/_hset`)·접근표·수정치·소비 묶음 목록을 버리고,
  주거의 캐시 필드 `psig`·`nsig`를 지우고 `sdm=-1, sdc=0`(모든 수요의 부족 일수를 다시 센다).
- expeditions: 매 스텝 팀 수를 거점 수에 다시 맞춘다.
workforce·utilities·finance·upgrades·space는 Cover 목록만 쓰므로 Cover를 다시 만들면 같이 "캐시 없음"이 된다.

### 차등 퍼즈 `godot/tests/sim_cache_fuzz.gd`
같은 씨앗의 두 시뮬(캐시 켬 / `no_cache`)에 같은 무작위 명령을 넣고 6스텝마다 `CityState` JSON 전체를 비교(주거의 `psig/nsig/sdm/sdc`만 뺀다).
명령: 칠하기(사각형·줄·흩어진 칸, 무작위 순서), 열린 시설 짓기(범위 안팎 무작위), 주거·시설 철거, 멈춤/재개(물·전기 부족과 회복 포함),
승급(무작위 자재), 계약 맺기·끊기, 디버그 돈·재고 몰아넣기와 재고 빼기(바닥), 정책 켜고 끄기, 연구 시작·취소, 탐험 보내기·받기,
층 채우기(`fill_floor` → 층 해금), 거래처 공개, `catch_up` 미접속 조각, 저장→불러오기 왕복. 홀수 씨앗은 첫 경제일에 주거만 칠한다
(통합에서 찾은 버그의 순서), 짝수 씨앗은 균형형 봇의 명령을 A에서 받아 B에 그대로 넣는다(승급·층 해금·계약·탐험까지 가게).
명령 결과(ok·reason)가 다르거나 상태가 다르면 첫 차이 경로와 최근 명령을 찍고 실패.

- 짧게(시험 묶음 안, 약 5초): `sim_test.sh`가 `-- mode=short seeds=2 days=3`로 부른다. 비교는 전체 정밀도(settle 없이 `to_dict` → full-precision JSON)라 저장 글 자릿수 밑의 끝자리 차이도 잡는다.
- 길게: `KOWLOON_NOSAVE=1 godot --headless --path godot -s res://tests/sim_cache_fuzz.gd -- mode=long` (씨앗 20 × 30경제일). `seeds= days= seed0= every=`로 바꿀 수 있다.
- 민감도 확인: 통합 패치(접근표가 바뀌면 `_hent/_hset` 비우기)를 되돌리면 짧은 모드 씨앗 2가 1.0일째에 `state.money`(세수)에서 어긋난다.
- 차이 난 주거를 통째로 보려면 `FUZZ_DUMP=1`.

### 퍼즈가 찾은 것
1. **(통합에서 이미 고친 것) 접근표가 바뀌어도 주거별 빠른 길(`_hent/_hset`)이 옛 묶음을 씀** — 퍼즈로 재현됨(패치를 되돌리면 씨앗 2가 1.0일째 세수에서 갈림), 패치가 맞는 자리임을 확인.
2. **settle() 뒤 "가라앉은 주거"가 반올림된 파생 값을 들고 있음** — 자정·저장의 `settle()`이 주거의 `tax`·`ratio` 등을 JSON 자릿수로 반올림하는데, 2단계를 건너뛴 주거와 `nsig`가 같은 주거는 다시 쓰지 않아 반올림 값이 남았다. 캐시 없는 계산은 매번 원래 값을 쓴다 → 끝자리(1e-15)가 갈리고 장부 합계·떠나는 시점(한 스텝)까지 번졌다(긴 모드 씨앗 1·6·8·12). 고침: `CityState.settle_n`(저장 안 함)이 바뀐 스텝은 건너뛰기·nsig 생략을 한 번 쉰다(하루 한 번 + 저장마다 한 스텝 전체 계산).
그 밖의 캐시(Cover·수정치·묶음 유효성·P2 재사용·탐험 팀 맞추기)에서는 차이가 나오지 않았다(고친 뒤 긴 모드 씨앗 20 × 30경제일 통과, 737초: 명령 약 6,300개(봇 승급 101·일반 승급 19 포함), 저장 왕복 98번, 미접속 61번, 4층까지 해금).

### 통합 패치 검토(needs `_pacc != _acc_ver` → `_hent/_hset` 비움)
맞는 자리다. 빠른 길은 주거의 접근 등급(ci)을 다시 보지 않으므로, 접근표(범위 시설의 가동·전기 원인 비트)가 바뀌면 묶음과 함께 버려야 한다.

그만큼 자주 비우지만(정확성 우선), 1,000채 탐침에서 스텝 시간은 그대로다(아래).

### 내가 정한 것(파트 C) — 번호, 이유
38. **no_cache의 Cover는 스텝 시작·명령 앞뒤마다 다시 만든다**(부를 때마다가 아니라). 부를 때마다는 퍼즈가 3배 느렸고, `layout_changed`를 빠뜨린 경로는 다음 스텝에 어차피 캐시 쪽과 갈려 잡힌다.
39. **퍼즈 비교는 전체 정밀도**. 저장 글 정밀도로만 보면 2번 문제가 장부에서 늦게, 원인과 먼 곳에서 드러났다.
40. **settle 뒤 한 스텝 전체 계산**으로 고침(건너뛰기 조건에 settle 횟수). 반대로 settle이 주거 파생 값을 건드리지 않게 하는 길도 있으나 저장 왕복 결정론(저장 글 = 반올림 값)을 바꾸게 되어 택하지 않음.
41. **층 진행 낱말 "쓰이는 칸"**(빈집 제외). "사람 사는 칸"은 시설 칸도 센다는 사실과 어긋나서.
42. **목표 판정은 debug 명령 뒤에는 그대로 안 한다**(원래 결정 유지 — 디버그 채우기로 보상이 쏟아지지 않게). 층 해금은 debug 뒤에도 본다(하네스 `fill_floor` 직후 HUD가 맞게).
43. **틱 안에서 생긴 변화(입주·승급 완료)로 이룬 목표는 여전히 4스텝 경계에서 판정**. 매 스텝 판정하면 Metrics를 매번 계산해야 하고, 지난 판정 기억을 상태 밖에 두면 저장 왕복 결정론이 깨진다. 층 해금은 원래 매 스텝(space 틱) 판정이라 입주 뒤 길어야 한 스텝(12.5초).
44. **Bot에 `recorded`(시험용 기록) 추가** — 봇 명령을 다른 시뮬에 그대로 넣으려고. 기본 null이면 아무 일도 안 한다.
