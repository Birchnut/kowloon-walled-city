## 4. 던전은 이렇게 만든다 (`DungeonGen.gd`)

1. 격자 위 무작위 걷기(오른쪽 3 : 위 1.4 : 아래 1.4 : 왼쪽 0.4)로 **본길 6~7방**(입구 → … → 두목). 막히면 다시.
2. 본길 중간 방에 **곁방 1~2개**(총 7~8방).
3. **깊이** = 입구에서 문 몇 개.
4. 방마다 깊이에 맞는 틀(26×16 타일, `run_rooms.json` 9종 + 입구 + 두목)을 겹치지 않게 골라 좌우·상하로 무작위로 뒤집는다.
5. 이웃 방을 2칸 폭 통로로 잇고 문 앞을 비운다. 입구에서 닿지 않는 칸의 물건은 지운다.
6. **적**: 방 예산 = 1 + 1.5×깊이 + 0.4×위험도. 틀의 표지(쥐 둥지 1, 들개 2, 경비원 3.5)를 무작위 순서로 예산만큼 켠다. 경쟁 고물상은 한 판에 많아야 1명.
7. **출구**: 입구의 "들어온 구멍" + 본길 깊이 2~3 방의 맨홀. 두목을 잡으면 두목 방에 뒷문.
8. **재고**: `run_begin`의 stock에서 큰 짐(두목 보상)을 먼저 떼고, **깊은 방의 더미부터** 묶음을 채운다. 얕은 더미는 자주 비어 있다(입구 방은 늘 1묶음). 깊이 2부터 더미의 25%는 **잠긴 사물함**(+1.8초, 소란 1.6배, 두 단계 깊은 물건). 그래서 한 판에 나올 수 있는 양은 늘 재고 이하다(시험이 검산).

## 5. 통합하는 사람에게 (진입점과 연결할 것)

```gdscript
var run := preload("res://expedition/RunSandbox.tscn").instantiate()
run.dest = "scrap_yard"        # 던전 id
run.standalone = false         # 창 크기·배율을 건드리지 않는다
run.run_finished.connect(func(result: Dictionary) -> void: run.queue_free())
add_child(run)                 # 시작 화면 → 줍기 → 결과 화면 → [도시로] 누르면 신호
```
- `run_result`는 **결과 화면이 뜨는 순간 `CityLink.result()`가 한 번 보낸다**. 신호(`run_finished`)는 "화면을 닫아도 된다"는 뜻이고 같은 result를 준다: `{dest, loot:{good:n}, outcome, finds:[String], carried, left, lost, found, time, kills, …}`.
- **확인할 파일은 `godot/expedition/CityLink.gd` 하나.** 지금은 `Game.cmd("run_begin")`이 "지금은 할 수 없는 일이다 (run_begin)"를 돌려주면 견본 재고(`run_goods.json` `sample_begin`)를 쓰고 결과는 출력만 한다. 명령이 생기면 저절로 진짜를 쓴다.
- 맞춰 볼 것: (1) 물건 id — `canned`(통조림)는 도시 goods에 **아직 없다**, `elec`는 도시 이름이 "전자 부품"(여기서는 "전자 폐품"으로 보인다). (2) 던전 id `scrap_yard`(도시 이름은 "고철 야적장"). (3) `run_begin`의 stock 값이 정수여야 한다(실수면 정수로 바꿔 씀). (4) 선택: `Game.query("run_ticker")`가 문자열 배열을 돌려주면 오른쪽 위 "성채 소식"에 진짜 소식이 뜬다.
- 줍는 동안 도시가 돌게 하려면 아무것도 안 해도 된다(이 장면은 트리를 멈추지 않는다. 멈춤 메뉴도 이 장면만 멈춘다).
- 화면: 내부적으로 480×270 근처의 저해상도를 정수 배율로 키운다(높이/270 반올림: 1080p ×4, 720p ×3). HUD는 원래 해상도. `standalone=false`이면 창의 content scale을 그대로 두고 보이는 영역 크기로 계산한다.

## 6. 규칙 요약 (v0)

| 것 | 예고(보이는 것) | 맞서는 법 |
|---|---|---|
| 쥐 떼(2~3마리, 체력 1) | 웅크리며 빨간 짧은 띠 + 찍찍 | 굴러 피하거나 먼저 친다. 휘두르는 소리·깡통 소리에 흩어진다 |
| 들개(체력 3) | 주위를 돌다 으르렁 + **빨간 긴 띠**(앞 절반은 옅게 따라오고, 굳으면 진하게 번쩍) | 띠가 굳으면 옆으로 구른다. 덮친 뒤 "헥헥"(0.75초)에 친다 |
| 경비원(체력 4, 한 대 1.5칸) | 노란 손전등 원뿔(벽에 잘림) → 머리 위 "?" 게이지 → 빨갛게 "!" 추격, 곤봉을 들면 빨간 부채꼴 | 원뿔 밖으로. 깡통을 던지면 그쪽을 보러 간다. **모르는 경비원 등 뒤에서 치면 2배("기습!")** |
| 경쟁 고물상 | 더미를 털고 "+철제" | 건드리지 않으면 무해. 때리면 덤비고, 눕히면 턴 것을 떨군다 |
| 무너지는 고철 산 | 가까이 가면 흔들리고 바닥에 **그림자 원**이 짙어진다(0.95초) | 원 밖으로. 적도 맞는다. 무너진 자리에 작은 더미(고물)가 남는다 |
| 누전 웅덩이 | 3.4초 주기: 파란 깜빡임(0.75초) → 번쩍(0.45초) | 박자 보고 건넌다. 적도 감전된다 |
| 두목 압축기 "큰형"(체력 20) | ① 내려찍기: 머리 밑 빨간 네모가 좁아짐 ② 침 뱉기: 바닥에 빨간 원 3~5개 ③ (체력 절반 아래) 쓸기: 방 전체 옅은 빨강 + **초록 "틈"** | ①을 피하면 머리가 1.5초 **끼여 노란 "약점!"** — 이때만 맞는다(깡통도 들어감) ② 원 밖으로 ③ 틈으로 가거나 구르기로 넘는다 |

- **소란**: 뒤지기 3.5/초, 맞히기 1, 경비원에게 들킴 10, 던짐 3, 무너짐 6, 가만히 있어도 0.2/초. 100이 차면 단계가 오르고 이 방의 먼 문에서 지원군(1단계 쥐 3 → 2단계 쥐 2·들개 1 → 3단계 경비원·쥐 2 → 4단계 이상 경비원·들개·쥐 2)이 오고, 그 뒤로는 1.15배씩 빨리 찬다.
- **배낭** 6칸, 칸마다 같은 물건 4묶음까지(설비 부품 2). 걸어가면 빨려 들어온다. 꽉 차면 발밑에 노란 테두리 + 안내.
- **결과**: 출구에서 E 0.9초 → `exit`(전부 내 것). 두목을 잡고 어느 출구로든 → `boss`(+큰 짐: 설비 부품 3·전자 폐품 4·도면). 체력 0 → `down`(묶음 절반(내림)을 무작위로 잃고 큰 짐도 잃음). 결과 화면: 들고 나온 것 / 두고 온 것 / 잃은 것 / 한 줄.

## 7. 스스로 정한 것 (번호 — 이유)

1. **방을 한 장의 이어진 지도로**(화면 넘김 아님): 쫓기며 방을 넘나드는 긴장, 불러오기 없음. 카메라는 마우스 쪽으로 22% 앞을 본다.
2. **저해상도 480×270 정수 배율**, HUD만 원래 해상도: 픽셀이 뭉개지지 않고 한글 글자는 또렷하게.
3. **물리 엔진 대신 자체 충돌**(타일 상자 + 모서리 보정 5px): 같은 코드가 사람·봇·배치에서 똑같이 돌고, 판당 0.5초로 수백 판을 돌릴 수 있다.
4. **체력 12 = 하트 6칸(반 칸 있음)**: 처음 하트 6(1칸씩)은 쥐 한 입이 체력의 1/6이라 너무 거칠었다(조정 T3·T15).
5. **기력(스태미나) 없음**: 구르기 쿨다운 0.42초로 대신. 이 규모에서 막대 하나 더는 읽을 거리만 늘린다.
6. **던질 것은 배낭 밖 "손" 3칸**: 던지기가 짐 칸과 다투지 않게. 깡통은 다시 주울 수 있고 벽돌은 깨진다.
7. **자동 줍기 + Tab 바꿔 담기**, 배낭을 여는 동안 시간 0.3배: 고르는 시간은 주되 위험은 남긴다.
8. **예고 색의 약속**: 빨강 = 곧 맞을 자리, 노랑 = 칠 기회·물건, 초록 = 출구·안전. 모든 공격 앞에 빨간 표시가 있다.
9. **예고는 앞 50%만 따라오고 나머지는 굳는다**(굳으면 진하게 번쩍): 처음엔 65%까지 따라와 사람이 반응할 시간이 0.2초뿐이었다(T16).
10. **두목은 공중의 압축 머리**(문형 기중기): 피하기 → 끼임 → 치기의 박자가 한눈에 보인다. 끼였을 때만 맞는다.
11. **두목 방을 잠그지 않는다**: 언제든 나갈 수 있어야 "더 갈까, 나갈까"가 산다.
12. **두목 보상 = 큰 짐(배낭 밖 1칸) + 도면**, 재고에서 미리 떼어 둔다: 재고 상한을 지키면서 "최대 보상"을 따로 보이게.
13. **쓰러지면 묶음의 절반(내림)을 무작위로 + 큰 짐**. 멈춤 메뉴의 "포기" = 쓰러짐(나가는 길을 공짜로 주지 않는다).
14. **출구는 E 0.9초**, 더미가 더 가까우면 더미가 먼저: 맨홀 옆 더미를 뒤지다 나가 버리는 일이 실제로 났다(T7에서 고침).
15. **깊은 방부터 재고를 채운다**, 얕은 더미는 자주 빔(입구 방만 예외): 앞사람들이 이미 털었다는 설정 + 더 들어갈 이유.
16. **잠긴 사물함**(설계의 "열기"): 오래·시끄럽게 따지만 좋은 것 — 소란과 바꾸는 선택.
17. **경쟁 고물상은 한 판에 0~1명**: 더미를 먼저 턴다는 압박만 준다. 아직 비중이 작다.
18. **반창고**: 더미의 30%에서 하트 1칸. 회복 없이는 판이 2분 안에 끝났다(T18).
19. **칸당 4묶음**(부품 2): 3묶음이면 2.4분이면 배낭이 차서 판이 짧았다(T17).
20. 물건 id: 통조림 `canned`(도시에 없음), 전자 폐품 `elec`, 던전 `scrap_yard` — 통합 때 확인.
21. 그림: 사람 3종은 rubberduck CC0(테두리를 덧그려 바닥에서 띄움), 나머지는 전부 코드로. 고철 산은 처음 그림이 다리 달린 사람처럼 보여서 두 번 다시 그렸다.
22. 화면 확인은 실제 창 PNG(`run_shot.sh`)와 조건부 뽑기(`shot_when`).
23. 자동 플레이어는 RunInput만 채운다(이동·조준·클릭·Space·E·Tab·칸). 반응 지연과 피할 확률로 실력을 나눈다.
24. **F2 = 자동 플레이**: 해 보기 전에 봇이 어떻게 노는지 볼 수 있게.

## 9. 아직 손맛이 안 좋은 곳 (솔직하게)

1. **사람이 직접 해 본 적이 없다.** 모든 확인은 입력 대본·자동 플레이·스크린샷이다. 마우스 조준의 감도, 휘두르기 부채꼴(120°, 27px)이 실제로 시원한지, 구르기 거리(약 50px)가 답답한지는 Jin이 해 봐야 안다.
2. **판 길이 3.0분은 봇 기준.** 봇은 길을 헤매지 않고 망설이지 않는다. 사람은 더 길 것이다(추측: 1.3~1.6배). 반대로 처음 하는 사람은 훨씬 많이 죽을 수 있다.
3. 늦게까지 버티면 소란이 5~8단계까지 올라 **지원군이 줄줄이** 온다(꼼꼼 욕심 평균 5.8단계). "오래 있으면 위험"은 되지만 후반이 단조롭다.
4. 적의 "맞았다"는 흰 번쩍임·밀림·글자("깨갱")뿐이다. 찌그러지기·튕겨 나가 구르기 같은 **슬랩스틱 동작이 없다.** 쥐(12px)는 작아서 떼로 겹치면 세기 어렵다.
5. 방 틀 안쪽 벽(2×2, 2×3 덩어리)이 **상자처럼** 보이고, 방마다 색이 같아 깊이가 달라도 분위기가 비슷하다.
6. 던지기는 날아갈 길을 미리 보여 주지 않는다(착지점 원만). 벽에 맞으면 그 자리에 떨어진다.
7. 두목: 들어갈 때 카메라 연출이 없고, 패턴이 3개라 두 번째 판부터 외워진다. 쓸기는 틈이 넓어 쉽다.
8. 배낭: 한 묶음만 덜어낼 수 없다(칸째로 내려놓음). 마우스를 칸 위에 올려도 설명이 없다.
9. 합성음은 삑삑 소리 수준이고, 배경 웅웅거림은 6초마다 이음새가 살짝 튄다.
10. 경쟁 고물상은 있으나 마나다(판의 60%에만, 한 명).
11. 패드·키 바꾸기 없음.

## D. 아직 약한 곳 (2차 뒤)

1. 여전히 **사람이 직접 해 본 적이 없다**. 슬랩스틱의 세기(돌기 속도·별·찌그러짐 35%)는 스크린샷으로만 봤다.
2. 사람 그림(16×32)은 여전히 남의 팩 그대로라 맞을 때 **표정이나 몸짓이 없다**(돌기·찌그러짐으로 대신).
3. 매립지는 **조정하지 않았다**(봇 몇 판으로 돌아가는 것만 확인). 물렁한 땅은 봇이 피하지 않는다.
4. 보통 봇의 판 길이 분포가 두 덩어리다(일찍 나가는 판 ~2분, 두목까지 가는 판 ~4분).
5. 투광등은 "시야가 넓어짐"뿐 화면 전체 밝기 변화는 없다(투광등 기둥의 빛 웅덩이만 밝아짐).
6. 덜렁이는 두목 방에 99% 닿는다(체력 1까지 밀어붙이는 성격) — 성격 값 문제이지 게임 문제는 아니다.
7. 소리는 효과음만 바뀌었고 음악·도시 배경 소리와 섞는 것(AudioDirector)은 통합 몫.
