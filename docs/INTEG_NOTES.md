# 통합 노트 v0.3 (브랜치 `integ`, 2026-11-11)

진짜 시뮬 + 진짜 뷰 + 진짜 UI만으로(견본 없음) 처음 하는 사람의 첫 접속을 끝까지 몰아 보고 고친 기록.
스크린샷은 `docs/shots/integ_*.png`(23장). 아래 "증거"의 파일 이름은 그 폴더 기준.

## 0. 한 번에 다시 보기

```
# 첫 접속 전체(폴리시 순서: 새 도시 → 오프닝을 진짜 터치로 → 판잣집 8 → 좌판·빗물받이 둘·텃밭 → 살피기 → 목표 버튼으로 탐험 거점 → 파견
#  → 집이 차서 위 줄 "승급할 수 있는 주거 n채" → 그 줄을 눌러 승급(목재, 시작 재고만 — 3채만) → 디버그 '탐험 +10분' → 수령
#  → 교역소·초 공방 → 헌 옷·유지 계약 → 디버그로 1층 채움 → 2층 칠하기), 약 2분
# 두 손가락 핀치 단계 확인: tools/shot.sh "" /tmp/p 200 540x960 skiptut script=res://tools/fixtures/pinch_check.json out=/tmp/p
tools/shot.sh "" /tmp/walk 6000 540x960 script=res://tools/fixtures/first_session.json out=/tmp/walk trace=1
# → /tmp/walk/wa*·wb*·wc*·wd*·we*.png, 출력의 [script]·[trace] 줄(못 찾음/시간 초과가 없으면 통과)
```
`script=` 문법은 `godot/tools/DevHarness.gd` 아래쪽 주석(tap·drag·press·press_in·cell·paint·target·jump·until·q·save·expr …).
모든 누름은 `Input.parse_input_event`의 **InputEventScreenTouch/Drag**(휴대폰과 같은 길, 마우스 흉내 포함)다. `cmd`·`dbg`는 준비용으로만 썼다(디버그 '탐험 +10분'은 성채 › 기록의 디버그 버튼을 눌렀다).

## 바깥(소유 밖) 수정 — 최소

1. **`godot/sim/systems/needs.gd`(SIM 소유, 첫 접속을 막았다)**: 접근표(시설 가동)가 바뀌어 묶음 캐시를 버릴 때 주거별 빠른 길 캐시(`_hent`, `_hset`)도 같이 버린다. 3줄. 재현: 새 도시 → 판잣집 8채 → 좌판·빗물받이·텃밭 → ×16으로 기다리면 떠돌이 8명(집마다 1명)에서 사흘이 지나도 안 늘고, 살피기는 시설이 가동 중인데도 "인력 부족". 고친 뒤 sim_test ALL PASS.
2. **`godot/view/CityView.gd`(VIEW)**: (a) 터치가 흉내 낸 마우스 이벤트(`device == DEVICE_ID_EMULATION`)는 무시 — 흉내 마우스가 터치보다 먼저 와서 칠하기 첫 칸이 두 번 들어가 획 전체가 지우개가 됐다(휴대폰·웹 모두). (b) 이 뷰가 누름을 받지 않은 손가락의 뗌은 탭이 아니다. (c) 끌기(pan)에도 카메라 한계, 위쪽 한계는 가장 높은 층 근처 — 두 손가락·끌기로 하늘만 보이는 곳까지 나갔다.

## (b) SIM에 넘길 것

1. **needs 캐시(위 1번)** — 넣은 수정이 맞는지 SIM-B가 확인해 줄 것(성능 탐침도). 다른 빠른 길(`_p2`, `fast2`)도 접근표 변경에 같은 문제가 있는지.
2. 거절 문장 조사: `"%s이(가) 모자란다"`(space.gd 230, 승급·연구 비슷), `"%s이(가) 단속으로 닫혀 있다"`(alerts.gd 143) → UI의 `UI.josa`처럼 받침으로 고르면 "철제가 모자란다".
3. 돈 문장에 천 단위 쉼표 없음: 미접속 요약 "금고 ₩349 → ₩33151 (+₩32802)", 단속 기록 "벌금 ₩320".
4. 정책 `bribe` 설명 "음성 시설 하나당 ₩/일" — 숫자가 비었다.
5. buildings.json 카지노 desc 끝 "[단속은 B 파트]" — 옛 메모가 화면에 나온다. 카지노 살피기 "단속 위험 +12/일" vs vice 질의 heat_per_day 3.6 — 둘 중 하나는 다른 단위(가동률 반영 전/후?)라 플레이어에게 엇갈린다.
6. `floor_progress.text` "2층이 열리려면 1층에 21칸 더" — 빈집은 세지 않는다는 걸 문장이 말하지 않아서 24채를 칠하고도 숫자가 그대로인 걸 보고 헷갈린다. 제안: "사람이 사는 칸 21개 더". 그리고 조건을 넘어도 다음 경제 시각(×1에서 최대 25초)까지 '곧 열린다'로 남는다 — 칠한 순간 판정하면 좋겠다.
7. 목표 달성 판정도 시각 단위라 승급 직후 hud.next_goal 이 잠깐 옛 목표다(위와 같음, 큰 문제는 아님).
8. `expeditions` 질의에 거점 공사 중(site) 정보가 없어 UI가 상태를 읽어 "짓는 중"을 판단한다 — `slots.building:int`를 주면 규칙 3을 지킬 수 있다. 교역 '집들이 찾는 것'도 UI가 info 를 계층마다 한 번 묻는다 — `economy.goods[].wanted:bool` 이 있으면 좋다.
9. 오프닝 제안: `tutorial` 명령이 int만 받아서 '끝남'을 1000으로 저장한다(UI 약속). `{step, done}`을 받으면 깔끔하다.
11. (폴리시) `expeditions.dests[].bonus` 구조화(`[{good,name,min,max,chance}]`) — UI가 지금 `bonus_text`를 파싱해 보장/운을 나눈다(UI_NOTES P7).
12. (폴리시) 목표 순서: 첫 승급이 목표 4(수령)보다 먼저 가능해졌다. 지금은 알림 줄이 알리지만, 목표 4·5 순서를 바꾸거나 목표 5를 '수령'과 동시에 열면 목표 카드도 승급을 말한다.
10. (반영됨 — 시작 재고 헌 옷 8·초 10) 첫 승급 문턱: 떠돌이 → 세입자 조건(헌 옷 + 등불)이 교역소 + 계약 둘 + 초 공방(원료 유지 계약)까지 요구해서 목표 5(g_t2_1)까지 처음 사람이 해야 할 일이 많다. 목표 문장에 "헌 옷·등불"을 넣거나, 첫 탐험 보상·시작 재고에 헌 옷·초 소량을 두면 첫 승급을 빨리 맛본다(밸런스 판단은 SIM).
